# co-secondbrain

프로젝트 단위 Second Brain 프레임워크 — Windows 데스크톱 앱.

이메일·회의 전사·Word·Excel·PowerPoint·PDF·Markdown을 넣으면 LLM이 점진적으로 **위키**를
짓고 유지합니다. 질의할 때마다 원본을 다시 훑는 대신, 축적된 위키가 답합니다.

**개인 로컬 세컨브레인이 기본**이고, 프로젝트 단위 **CO 영역**은 사내 로컬 서버(CO-Hub)를
통해 동료와 주고받습니다. 클라우드 컴포넌트 없음.

> 현재 상태: **계획 v0.8 · M0 완료.** 사내 W1 실측으로 읽기 경로 확정. 검증 코드는 `spikes/`, 결과는 `docs/M0-RESULTS.md`.

```
[PC A]  personal/  +  projects/ACME/ ──┐
                                        ├── 사내망 HTTP ──▶ [CO-Hub]
[PC B]  personal/  +  projects/ACME/ ──┘                     SQLite + blob
                                                             LLM 없음. 동기화만.
```

## 구현 완료 시 최종 프로덕트

아래는 [`docs/PLAN.md`](docs/PLAN.md) 기준 v1 범위의 최종 모습입니다. 계획 문서에서 가져온
내용입니다. 현재 구현 상태는 이 절 끝의 표를 보십시오.

### 혼자 쓸 때

Windows에 앱을 설치하고 `personal/` 볼트를 하나 만드는 데서 시작합니다. 이메일(`.eml`
`.msg`), 회의 전사(`.vtt` `.srt` `.txt`), Word·Excel·PPTX·PDF·Markdown 파일을 앱에
드롭하면 두 단계를 거칩니다.

1. **로컬 추출** — 텍스트와 앵커(페이지·슬라이드·셀·타임코드 좌표)를 로컬에서 무료로
   뽑습니다. 이메일 스레드는 `In-Reply-To` 헤더로, 엑셀 의존 관계는 수식의 셀 참조로 뽑는
   구조도 이 단계에서 나옵니다. LLM은 아직 관여하지 않으며 결과는 전부 `EXTRACTED`입니다.
2. **위키 갱신** — Claude Code · Gemini · Codex CLI 중 설치된 것을 골라 호출합니다. LLM은
   새 엔티티·개념 페이지를 만들거나 기존 페이지를 갱신하는 **ChangeSet**(변경안)을 냅니다.
   한 건씩 요약을 확인하고 승인하는 감독 모드, 여러 건을 모아 마지막에 검토하는 일괄
   모드 중 고를 수 있습니다.

**LLM은 디스크에 직접 쓰지 않습니다.** ChangeSet은 사람이 diff 화면에서 승인해야 파일로
반영됩니다. 모든 주장에는 `[^src-kickoff#slide-12]` 같은 앵커 인용이 붙습니다. 클릭하면
원본의 그 위치로 점프합니다. 신뢰도는 `EXTRACTED`(원문에 명시) · `INFERRED`(추론, 5단계
점수) · `AMBIGUOUS`(불확실) 중 하나로 표시됩니다.

`index.md`는 각 페이지의 요약에서 앱이 자동으로 조립하는 카탈로그입니다. `log.md`는
`## [2026-09-03] ingest | 킥오프 발표.pptx` 형식의 시간순 기록입니다. 질의는 검색창에
물으면 한국어 하이브리드 검색(FTS5 + trigram)으로 후보 페이지를 고른 뒤 LLM이 인용을
붙여 답합니다. 그 결과는 `synthesis/` 페이지로 보관됩니다.

앱은 계산 검사 7종(고아 페이지·누락 상호참조·출처 없는 주장·깨진 앵커·엔티티 중복
후보·`AMBIGUOUS` 누적·한국어 AI 티)을 LLM 없이 상시 돌립니다. LLM 판단이 필요한 4종
(모순·낡은 주장·언급되지만 없는 페이지·데이터 공백)만 따로 호출합니다. 결과는 전부
제안이고 자동으로 고치지 않습니다 — 오탐이 하나만 있어도 사람이 Lint 자체를 무시하게
되기 때문입니다.

볼트는 폴더와 마크다운일 뿐입니다. Obsidian으로 열어도 그대로 작동합니다. 앱을 지워도
지식은 파일로 남습니다.

### 동료와 같이 쓸 때

프로젝트마다 `projects/ACME/` 같은 **CO 영역**이 있습니다. 사내 로컬 서버 **CO-Hub**(사내망
IP 주소)가 팀원 사이를 중계합니다. CO-Hub는 SQLite와 블롭 저장소일 뿐 LLM도 비즈니스
로직도 없는 "멍청한" 동기화 서버입니다 — 서버가 죽어도 각자 로컬 미러로 계속 작업할 수
있습니다.

- CO 원본을 곧바로 인제스트하거나, 개인 위키 페이지를 **Contribute**(공유 전문을 보여주는
  검토 화면 필수 경유)로 올립니다.
- 동료가 만든 CO 페이지는 **Adopt**로 개인 위키에 복제합니다. 원본이 갱신되면 "채택본
  낡음" 배지가 뜹니다.
- 개인 → CO 링크는 허용하지만 CO → 개인 링크는 저장 시점에 차단합니다. 동료에겐 영원히
  깨진 링크입니다. 개인 볼트에만 있는 페이지가 존재한다는 사실 자체가 새어 나가기
  때문입니다.
- 동시 수정은 낙관적 동시성(`If-Match` → 충돌 시 409 → 3-way 병합)으로 처리합니다.
  오프라인 작업 후 재접속하면 충돌을 해결합니다.

### 의도적으로 없는 것

클라우드 연결이 없고(외부로 나가는 통로는 사내 예외로 허용된 CLI 3종뿐), 로컬 LLM도
텔레메트리·자동 업데이트·크래시 리포터도 없습니다. 자동 병합·자동 재작성도 없습니다 —
디스크에 닿기 전 마지막 관문은 항상 사람의 승인입니다.

## 확정된 선택

- **Electron + TypeScript**, NSIS 설치본
- LLM은 **Claude Code / Gemini / Codex CLI 3종** — 사내에서 예외적으로 허용된 통로.
  앱이 설치된 것을 탐지해 목록에 올린다. 로컬 LLM 사용 안 함
- **작업 종류별 공급자 라우팅** — 토큰을 많이 먹지만 판단이 가벼운 작업(대량 백로그,
  Lint 전수 검사, 중복 후보)은 상한이 느슨한 CLI로. 교체는 배치 단위
- 읽기 경로는 **앱 내장 MCP 서버** (사내 실측으로 `--mcp-config` 경로 확인).
  쓰기(ChangeSet 생성)는 CLI 실행 + 스키마 강제
- 신뢰도는 주장 단위 **EXTRACTED / INFERRED / AMBIGUOUS** + 이산 점수 루브릭.
  "이 문장이 원본에 적혀 있었나, 추론인가"를 항상 구분
- 위키는 **Obsidian 호환** 마크다운 — wikilink, YAML front-matter, 고정 첨부 폴더.
  앱이 Obsidian 역할을 하되 병행 사용을 막지 않음
- 개인 금고는 **일반 폴더**. Git 의존성 없음. 앱 내부 스냅샷으로 되돌리기
- CO 영역은 **허브 DB가 버전 관리**. 낙관적 동시성(`If-Match` → 409 → 3-way 병합).
  파일 잠금 없음
- 텔레메트리·자동업데이트·크래시 리포터 없음

## 핵심 설계 결정 3가지

1. **LLM은 디스크에 직접 쓰지 않는다.** 변경안(ChangeSet)을 내고 사람이 diff로 승인하면
   앱이 적용한다. 업무용에 필요한 감사 추적과 되돌리기가 여기서 나온다.
2. **모든 주장에 앵커 인용.** `[^src-kickoff#slide-12]`를 클릭하면 실제 PPT 12쪽으로 점프한다.
   출처 없는 문장은 Lint가 잡는다.
3. **허브는 멍청하다.** LLM도 비즈니스 로직도 없다. 서버가 죽어도 로컬 미러로 계속 일한다.
4. **공짜로 뽑을 수 있는 구조는 LLM에게 묻지 않는다.** 이메일 스레드는 `In-Reply-To`
   헤더로, 엑셀 의존 관계는 수식의 셀 참조로, 고아 페이지는 링크 그래프로 계산한다.
5. **생성물의 한국어 품질도 검사한다. 단 고쳐 쓰지는 않는다.** 번역투·분열문·부정 대구를
   Lint가 짚어 주되(오탐 0), 재작성은 하지 않는다 — 앵커 인용이 붙은 문장을 다시 쓰면
   인용과 주장의 대응이 흐트러진다.

## M0에서 측정이 뒤집은 것

1. **비용의 대부분은 우리 문서가 아니라 CLI 자체의 고정 오버헤드**(약 3만 토큰).
   문서 4줄에 $0.13. 세션을 재개하면 62% 절감 → **배치 처리가 최적화가 아니라 필수**.
2. **한글 자모 분해는 유사도를 오히려 악화시킨다.** 도움이 될 거라 예상했으나 모든 임계값에서
   오병합이 같거나 더 많았음. 미채택.
3. **의외의 연결은 허브 노드를 빼야 한다.** 안 빼면 순위가 오염됨. 정답 포착 1/3 → 3/3.
4. **한국어 작문 규칙을 주입해도 개선이 확인되지 않았다.** 오히려 금지된 패턴(연결어미 뒤
   쉼표)이 1건 주입됐다. n=1이라 결론은 아니지만, "규칙을 넣으면 좋아진다"고 적을 근거는
   없다. M2에서 표본 20건 이상으로 재측정한다.

차용한 파라미터도 한국어에서 두 개가 틀렸습니다 — 엔트로피 게이트에 길이 하한이 필요하고,
Jaro-Winkler 임계는 0.92가 아니라 0.96이어야 합니다.

한국어 정규식에서도 같은 계열의 함정 3가지를 실측으로 찾았습니다: `\b`는 한글 경계에서
동작하지 않고, 조사 이형태(핵심'은' / 문제'는')를 둘 다 받아야 하며, 분열문 탐지 span이
절 경계를 넘어가면 정상 문장을 오탐합니다.

## 다음 단계

**W1 완료.** 사내 실측 결과:

```
1 CLI   claude=2.1.260 gemini=0.58.0 codex=X
2 설정  cfg=OK add=OK
3 연결  probe=OK 기존=-
4 mpm   O
```

→ **내장 MCP 서버(안 B) 확정.** 남은 항목은 전부 M1과 병행 가능합니다.

두 가지가 계획을 바꿨습니다.

1. **Gemini 폴더 신뢰 게이트** — 신뢰되지 않은 폴더에서 MCP를 끕니다. 우리는 격리 임시
   디렉터리를 쓰므로 항상 걸립니다. `--skip-trust`로 통과되는 것까지 확인했습니다.
2. **`--mcp-config` 채택** — `claude mcp add`(설정 파일 기록)가 아니라 호출 단위 설정.
   `--strict-mcp-config`로 사내 기존 MCP 서버를 격리합니다.

`codex=X`는 그 PC에 없다는 뜻일 뿐, **CLI 3종 지원은 유지**합니다.

M1 착수 가능.
