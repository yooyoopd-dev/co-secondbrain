# 공급자 라우팅 — 토큰 상한이 다른 CLI를 섞어 쓰기

사내 PC에서 Claude Code·Codex는 **토큰 상한**이 있고 Gemini는 상한이 훨씬 느슨합니다.
토큰을 많이 먹지만 판단이 단순한 작업을 Gemini로 보내고, 사용자가 원할 때 갈아탈 수 있는
구조를 정의합니다.

관련: [`PLAN.md`](PLAN.md) §7 · [`M0-RESULTS.md`](M0-RESULTS.md) §1.3

---

## 0. 전제 두 가지를 먼저 정정한다

### ① 문서 파싱은 이미 LLM을 쓰지 않는다

"문서 db 파싱 같이 단순하지만 토큰이 많이 드는 작업"이라고 하셨는데, **우리 설계에서 문서
파싱은 토큰을 한 톨도 쓰지 않습니다.**

`PLAN.md` §6.1(텍스트+앵커)과 §6.2(구조 추출)는 전부 로컬 라이브러리입니다.
M0에서 7/7 실측했습니다 — docx 제목 트리, xlsx 수식 의존 그래프, pptx 슬라이드+노트,
pdf 텍스트, 이메일 스레드 복원, vtt 화자 턴, 스캔본 감지. 걸린 시간은 전부 합쳐 500ms 미만.

**이건 라우팅 대상이 아니라 이미 해결된 항목입니다.** 진짜 토큰을 먹는 곳은 §1입니다.

### ② "토큰 무제한"은 제가 확인할 수 없다

Gemini CLI의 사내 쿼터가 실제로 무제한인지, 분당·일당 요청 상한이 있는지 **모릅니다.**
공개 무료 티어에는 요청 수 제한이 있는 것으로 알고 있으나 사내 계약 조건은 확인 불가입니다.

**그래서 이 문서는 "무제한"이 아니라 "상한이 서로 다른 두 공급자"로 설계합니다.**
실제 상한이 얼마든 설계는 그대로 성립하고, 상한이 알려지면 §4의 임계값만 채우면 됩니다.

## 1. 진짜 토큰을 먹는 곳

M0 실측(`M0-RESULTS.md` §1.3)에서 나온 핵심: **비용의 대부분이 우리 문서가 아니라 CLI 자체의
고정 오버헤드**입니다.

```
프로세스 1회당 고정 오버헤드 ≈ 30,000 토큰   (Claude Code 시스템 프롬프트 + 도구 정의)
세션 재개 시 → cache 생성이 cache 읽기로 전환
```

이 구조에서 토큰 소비 순위는 이렇습니다.

| # | 작업 | 토큰량 | 판단 비중 | 스키마 필요 | Gemini 후보? |
|---|---|---|---|---|---|
| 1 | **초기 대량 백로그 인제스트** | **최대** | 중간 (반복적) | 필요 | ✅ **1순위** |
| 2 | **Lint 전수 검사** (모순·낡은주장·개념누락·공백 4종) | **큼** | 중간 | 필요 | ✅ **2순위** |
| 3 | **엔티티 중복 애매 구간 배치 판정** | 중간 | 낮음 | 필요 | ✅ **3순위** |
| 4 | 일상 인제스트 (한 건씩 감독 모드) | 중간 | **높음** | 필요 | ❌ |
| 5 | 질의 답변 | 중간 | **높음** | 불필요(산문) | ❌ |
| 6 | synthesis 페이지 작성 | 중간 | **높음** | 불필요 | ❌ |
| 7 | 스키마 개정 제안 | 작음 | **높음** | 필요 | ❌ |

### 1번이 압도적인 이유

원본 500건을 처음 넣을 때, 고정 오버헤드만 계산하면:

```
문서당 프로세스   500회 × 30k = 15,000,000 토큰   ← 순수 오버헤드
10건 배치        50회 × 30k =  1,500,000 토큰   ← 10배 절감
```

여기에 문서 본문·위키 페이지·출력이 더해집니다. **초기 이관 한 번에 수백만~수천만 토큰**이
들 수 있고, 이게 상한 있는 공급자를 태워 먹는 주범입니다.

### 2번 Lint 전수 검사

M0 실측 기준 위키 페이지 1장이 1,114 B(한국어, front-matter 포함). 1,500장이면 약 1.7 MB.
LLM 판단 검사 4종이 이걸 훑습니다.

⚠️ **한국어 문자 수 → 토큰 수 환산은 측정하지 않았습니다.** 한국어는 영어보다 토큰을 많이
먹는 것으로 알려져 있으나 배수는 확인 불가입니다. **W10으로 남깁니다.**

## 2. 작업을 분류하는 축은 "단순함"이 아니라 세 가지다

"단순한 작업을 Gemini로"가 직관이지만, 실제로 갈리는 축은 셋입니다.

| 축 | 의미 | Gemini로 보내도 되는 쪽 |
|---|---|---|
| **스키마 필요** | ChangeSet 같은 구조화 출력이 필요한가 | 필요해도 가능(§7의 B등급 경로) |
| **판단 비중** | 틀리면 위키에 오염이 남는가 | **낮은 쪽만** |
| **토큰량** | 상한을 태우는가 | **큰 쪽** |

**판단 비중이 진짜 기준입니다.** 위키는 누적 자산이라 잘못된 주장이 한 번 들어가면
나중에 그 위에 다른 페이지가 쌓입니다. 되돌리기 비용이 비대칭입니다.

그래서 §1의 표에서 4·5·6·7은 토큰량과 무관하게 A등급에 남깁니다.

## 3. 라우팅 정책

```ts
type TaskKind =
  | 'ingest.batch'      // 대량 백로그        → 토큰 큼, 판단 중간
  | 'ingest.single'     // 감독 모드 한 건    → 판단 높음
  | 'lint.judgment'     // Lint LLM 4종      → 토큰 큼, 판단 중간
  | 'dedup.ambiguous'   // 중복 애매 구간     → 판단 낮음
  | 'query'             // 질의 답변          → 판단 높음
  | 'synthesis'         // 합성 페이지        → 판단 높음
  | 'schema.propose';   // 스키마 개정 제안   → 판단 높음

interface RoutingRule {
  kind: TaskKind;
  preferred: ProviderId;      // 기본 공급자
  allowFallback: boolean;     // 쿼터 소진 시 자동 전환 허용
  requiresSchema: boolean;
}
```

기본 정책 (사용자가 설정에서 통째로 바꿀 수 있음):

| 작업 | 기본 | 자동 폴백 | 근거 |
|---|---|---|---|
| `ingest.batch` | **Gemini** | — | 토큰 최대, 반복적. 애초에 여기로 보냄 |
| `lint.judgment` | **Gemini** | — | 전수 스캔. 결과는 어차피 사람이 검토 |
| `dedup.ambiguous` | **Gemini** | — | 후보 제시일 뿐, 병합은 사람 승인 |
| `ingest.single` | A등급 | ✅ 허용 | 감독 모드. 사람이 옆에서 봄 |
| `query` | A등급 | ✅ 허용 | 답변 품질이 곧 신뢰 |
| `synthesis` | A등급 | ✅ 허용 | 위키에 남는 산문 |
| `schema.propose` | A등급 | ❌ **금지** | 스키마가 틀리면 이후 전부가 틀어짐 |

**`schema.propose`만 폴백을 금지합니다.** 스키마는 다른 모든 작업의 계약이라 여기서 품질이
떨어지면 손상이 전파됩니다.

## 4. 사용자가 갈아타는 세 단계

### 4.1 전역 기본 (설정 화면)

공급자 목록에 설치된 CLI만 뜹니다(`detect()`). 미설치는 회색 + 설치 안내.

```
LLM 공급자
  ● Claude Code   2.1.260   [스키마 강제]  잔여 추정 —
  ○ Codex         미설치     [설치 안내]
  ○ Gemini        0.58.0    [앱 검증 필요]
```

### 4.2 작업 종류별 오버라이드

§3의 표를 그대로 보여주고 각 행의 공급자를 바꿀 수 있게 합니다.
"이 작업은 무엇이고 왜 이 공급자인가"를 한 줄로 같이 표시합니다.

### 4.3 실행 직전 교체 — ★ 배치 단위로만 바꾼다

인제스트 시작 버튼 옆에 공급자 선택을 둡니다.

```
[ 인제스트 시작 ]   공급자: [Gemini ▾]   문서 47건 · 예상 5배치
```

**배치 도중에는 바꿀 수 없습니다.** 세션 재개(`--resume`)로 고정 오버헤드를 아끼는데
공급자를 바꾸면 세션이 끊깁니다. 중간 교체는 절감을 버리면서 결과 일관성만 해칩니다.

바꾸려면 **현재 배치를 끝내고** 다음 배치부터 적용됩니다. 이미 승인된 것은 그대로 둡니다.

## 5. 쿼터 소진 처리

### 5.1 앱이 아는 것과 모르는 것

**압니다** — Claude Code의 `--output-format json` 응답에 `total_cost_usd`와 `modelUsage`가
들어 있습니다(M0 실측 확인). 누적하면 **소비량**을 정확히 추적할 수 있습니다.

**모릅니다** — **남은 쿼터**는 응답에 없습니다. 사내 계약 상한도 앱이 알 수 없습니다.

### 5.2 그래서 이렇게 한다

```
1. 앱이 공급자별 누적 소비를 기록한다 (일·주·월)
2. 사용자가 상한을 직접 입력한다 (설정: "Claude 월 상한 ___ 토큰")
3. 80% 도달 → 경고 배지
4. 100% 도달 → allowFallback=true 인 작업만 Gemini로 자동 전환, 사용자에게 알림
5. 실제 쿼터 오류(429·quota)가 나면 → 즉시 폴백 + 로그 기록
```

**상한을 사용자가 입력하는 이유:** 추측한 값으로 자동 전환하면 멀쩡한 쿼터를 두고
품질을 낮추게 됩니다. 모르는 값은 묻습니다.

### 5.3 배치 중간에 쿼터가 터지면

```
배치 10건 중 6건 처리 후 429
  → 현재 배치 중단. 처리된 6건의 ChangeSet은 보존(검토 대기)
  → 남은 4건으로 새 배치를 Gemini에서 시작
  → 사용자에게 "6건은 Claude, 4건은 Gemini로 처리됨" 표시
```

**이미 만들어진 ChangeSet을 버리지 않습니다.** 승인 전이라 손실이 아니고, 다시 만들면
토큰을 또 씁니다.

## 6. ★ 품질 하한은 CLI와 무관하게 앱이 강제한다

이게 이 설계의 핵심이고, **공급자 교체를 안전하게 만드는 유일한 근거**입니다.

어느 CLI가 만들었든 ChangeSet은 다음을 **전부** 통과해야 디스크에 닿습니다.

| # | 검사 | 주체 | 이미 계획에 있나 |
|---|---|---|---|
| 1 | ChangeSet JSON Schema 검증 | 앱 | §7.1 |
| 2 | `path` 정규식 (`^wiki/(sources\|entities\|concepts\|synthesis)/[a-z0-9-]+\.md$`) | 앱 | §7.1 (M0에서 모델이 실제로 어김) |
| 3 | `sanitizeTitle` — 경로 탈출·예약어 | 앱 | §9.2 (14/14 검증) |
| 4 | 앵커 인용 존재·형식 | 앱 | §3.1 |
| 5 | 인용된 `src-id#anchor`가 실재하는지 | 앱 | §4 Lint #8 |
| 6 | 한국어 AI 티 (Lint #11) | 앱 | §4 (오탐 0 검증) |
| 7 | `baseHash` 낙관적 동시성 | 앱 | §7.1 |
| 8 | **diff 승인** | **사람** | §3 원칙 3 |

**8개 중 7개가 앱의 결정론적 검사이고, 마지막은 사람입니다.** LLM이 통과하는 관문이 아닙니다.

따라서 공급자를 바꿔서 나빠질 수 있는 것은 **"내용의 질"**(요약이 얼마나 정확한가, 추론이
타당한가)이지 **"형식의 안전"**이 아닙니다. 형식 사고는 공급자와 무관하게 막힙니다.

이 사실이 §3에서 판단 비중이 낮은 작업만 Gemini로 보내는 근거입니다 — 남는 위험이
정확히 "내용의 질"뿐이므로, 질이 덜 중요한 작업만 고르면 됩니다.

## 7. B등급(Gemini) 경로 — 스키마 강제가 없다

M0 확인: Gemini CLI에는 `--json-schema`(Claude Code)·`--output-schema`(Codex)에 해당하는
플래그가 **없습니다.**

```
1. 프롬프트에 JSON Schema 를 본문으로 넣고 "이 스키마에 맞는 JSON만 출력" 지시
2. stdout 에서 펜스드 ```json 블록 회수
3. 앱에서 JSON Schema 검증 (ajv)
4. 실패 시 → 검증 오류 메시지를 붙여 1회 재요청
5. 두 번째도 실패 → 그 문서를 실패 목록에 넣고 배치는 계속. 사용자에게 표시
```

**재시도는 1회로 고정합니다.** §9.4의 비용 상한과 같은 이유입니다 — 무한 재시도는 상한이
느슨한 공급자에서도 시간을 태웁니다.

### Gemini 고유 제약

- **폴더 신뢰 게이트** — 모든 호출에 `--skip-trust` 필수 (`PLAN.md` §7.2)
- 지시 파일명은 `GEMINI.md` (M0 확정)
- 승인 모드는 `--approval-mode yolo` 또는 `-y`

## 8. 어느 CLI가 만들었는지 기록한다

공급자를 섞으면 **나중에 "이 페이지들만 이상하다"를 추적할 수 있어야 합니다.**

front-matter에 한 줄 추가:

```yaml
generated_by: gemini/0.58.0      # 또는 claude-code/2.1.260, codex/0.153.2
```

journal에도 남깁니다:

```jsonl
{"kind":"ingest","provider":"gemini/0.58.0","docs":10,"tokens":142000,"at":"2026-09-04T..."}
```

이걸로 가능해지는 것:

- 공급자별 Lint #11 점수 비교 → **품질 차이를 실측**할 수 있음
- 특정 공급자로 만든 페이지만 골라 재생성
- 공급자별 실제 토큰 소비 집계

**§3의 기본 정책은 지금 추측입니다.** 이 기록이 쌓이면 추측을 실측으로 바꿉니다.
