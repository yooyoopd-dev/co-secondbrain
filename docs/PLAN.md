# co-secondbrain — 프로젝트 단위 Second Brain 프레임워크

> Windows 데스크톱 앱. 이메일·회의 전사·Word·Excel·PowerPoint·PDF·Markdown을 받아
> LLM이 **점진적으로 위키를 짓고 유지**한다.
> 개인 로컬 세컨브레인이 기본이고, 프로젝트 단위 **CO 영역**은 사내 로컬 서버를 통해
> 동료와 주고받는다.

상태: **계획 v0.8**. M0 완료 + 공급자 라우팅 설계 반영.

- 기반 패턴: Karpathy "LLM Wiki" — 원문 전문 확인 후 반영.
  정리본 [`REFERENCE-llm-wiki.md`](REFERENCE-llm-wiki.md), 변형 내역은 그 문서 §9
- **공급자 라우팅: [`PROVIDER-ROUTING.md`](PROVIDER-ROUTING.md)** — 토큰 상한이 다른 CLI를 섞어 쓰기

## 2. 두 개의 공간 — 개인과 CO

```
%USERPROFILE%\SecondBrain\
│
├─ personal/                    ← 개인 세컨브레인 (기본)
│   └─ 외부로 나가지 않음. LLM CLI에만 필요한 만큼 전달됨
│
└─ projects/
    ├─ ACME/                    ← CO 영역: 허브 공간의 로컬 미러
    └─ BETA/
```

두 공간의 **내부 구조는 완전히 동일**합니다. 같은 엔진, 같은 인제스트, 같은 질의.
차이는 **동기화 대상이 있느냐**뿐입니다.

### 공간 사이의 두 가지 명시적 행위

동기화는 자동으로 일어나지 않습니다. 사람이 고릅니다.

| 행위 | 방향 | 내용 |
|---|---|---|
| **Contribute** | 개인 → CO | 공유될 내용을 전문으로 보여주는 검토 화면 필수 경유. 실수로 사적 메모가 나가는 것을 막는 유일한 장치 |
| **Adopt** | CO → 개인 | CO 페이지를 개인 위키로 복제. `derived_from: co://ACME/entities/acme-corp@v12` 기록. 원본이 갱신되면 "채택본 낡음" 배지 |

CO 영역에 원본을 **직접 인제스트**하는 것도 가능합니다(업무 문서는 대개 이쪽).

### 링크 방향 규칙

- 개인 → CO 링크: **허용** (`[[co:ACME/엔티티/에이콤]]`)
- CO → 개인 링크: **금지.** 저장 전 검증기가 차단

금지 이유: 동료에겐 영원히 깨진 링크이고, "누군가의 사적 페이지가 존재한다"는 사실 자체가
새어 나갑니다.

## 3. Vault 내부 구조

```
<Space>/
├─ sources/                     # 원본. 앱이 절대 수정하지 않음
├─ extracted/                   # 결정론적 추출. LLM 미개입. 언제든 재생성
│   ├─ <name>.md                #   본문 텍스트
│   ├─ <name>.anchors.json      #   페이지/슬라이드/셀/타임코드 좌표
│   └─ <name>.structure.json    #   ★ 구조 관계 (§6.2)
│
├─ wiki/                        # ★ LLM 소유. Obsidian 호환 마크다운
│   ├─ overview.md
│   ├─ sources/  entities/  concepts/  synthesis/
│
├─ assets/                      # 이미지 (Obsidian 첨부 폴더 규약)
├─ schema/
│   ├─ AGENTS.md                # ★ 정본 스키마
│   └─ taxonomy.md
├─ index.md                     # 카탈로그 (§5)
├─ log.md                       # 시간순 추가 전용 (§5)
├─ .sbignore                    # 무시 규칙 (§9.3)
│
└─ .sb/                         # 앱 내부. 위키가 아님
    ├─ config.json
    ├─ catalog.sqlite           # 검색 색인 3종 + 링크 그래프 캐시. 재생성 가능
    │                           #   fp=unicode61(접두) ft=trigram docs=원문(LIKE 폴백)
    ├─ cache/                   # ★ 시맨틱 캐시 (§9.1)
    ├─ manifest.json            # ★ 성공 완료 시에만 기록 (§9.1)
    ├─ history/                 # 스냅샷
    └─ sync/                    # CO 영역만
```

### 설계 원칙 6가지

1. **디스크가 진실이다.** SQLite는 재생성 가능한 캐시. 앱을 지워도 지식은 마크다운으로 남는다.
2. **Obsidian 호환을 유지한다.** wikilink `[[ ]]`, YAML front-matter, 고정 첨부 폴더.
   앱은 Obsidian을 **대체**하지만 **배제하지 않는다.**
3. **LLM은 디스크에 직접 쓰지 않는다.** ChangeSet을 내고 사람이 diff로 승인하면 앱이 적용한다.
4. **모든 주장에 앵커 인용과 신뢰도 태그.** §3.1.
5. **스키마는 공동 진화한다.** 앱에 스키마 편집기가 있고, LLM이 개정을 제안할 수 있다.
6. **생성물의 한국어 품질도 계약이다.** "AI가 쓴 티"가 나는 문장은 업무 문서로서 신뢰를
   잃는다. 예방(§9.6)과 검출(Lint #11)을 둘 다 둔다. 단 **재작성은 하지 않는다** —
   앵커 인용이 붙은 문장을 다시 쓰면 인용과 주장의 대응이 흐트러진다.

### 3.1 신뢰도 — 3분류 + 이산 루브릭

v0.2의 `confidence: high | medium | low`는 **의미가 모호해 폐기**합니다.
"high"가 무슨 뜻인지 사람마다 다르게 읽힙니다. 대신 **인식론적으로 명확한** 3분류를
**페이지가 아니라 주장 단위**로 답니다. (근거: `REVIEW-graphify.md` §1.A)

| 태그 | 의미 | 처리 |
|---|---|---|
| `EXTRACTED` | 원본에 **명시**돼 있음 | 기본. 배지 없음 |
| `INFERRED` | 모델의 추론. 점수 동반 | 점수에 따라 표시 |
| `AMBIGUOUS` | 불확실 | **Lint 결과함으로 자동 라우팅** |

`INFERRED`의 점수는 자유 실수가 아니라 **다섯 개 중 택일**입니다.
모델에게 "0~1 사이로 매겨라"라고 하면 뭉개진 값이 나오고, 고르라고 하면 일관됩니다.

```
0.95  거의 확실 — 명시적 교차 참조, 타당한 대상이 하나뿐
0.85  강한 근거 — 명명과 맥락이 일치
0.75  타당함    — 맥락상 그럴듯하나 명시적이지 않음
0.65  약함      — 이름 유사성뿐
0.55  추측
```

업무 위키에서 "계약 갱신일은 2027-01이다"가 계약서에 적혀 있는지(EXTRACTED)
메일 정황으로 추론한 것인지(INFERRED 0.75)는 결정적으로 다릅니다.

### front-matter 계약

```yaml
---
id: ent-acme-corp
type: entity              # source | entity | concept | synthesis | overview
title: 에이콤(주)
summary: 2026년 킥오프의 주 협력사. 계약 갱신일에 문서 간 불일치 있음.   # 300자 상한
aliases: [Acme, ACME, 에이콤]      # Lint #9가 후보를 제안, 사람이 승인
tags: [협력사, 계약]
claims:                            # ★ 주장 단위 신뢰도
  - text: 계약 갱신일은 2027-01-15
    source: src-2026-09-03-kickoff#slide-12
    confidence: EXTRACTED
  - text: 갱신 협상 주체는 구매팀
    source: src-2026-08-20-mail-a41f#body
    confidence: INFERRED
    score: 0.75
open_questions:
  - 계약 갱신일이 문서마다 다름 (2027-01 vs 2027-03)
derived_from: null        # CO 페이지를 채택한 경우 co://ACME/...@v12
generated_by: claude-code/2.1.260   # 어느 CLI가 만들었는지 (공급자 품질 추적용)
updated: 2026-09-03T10:22:00+09:00
updated_by: hong@corp
---
```

`summary`가 있는 이유: 원문의 index.md 형식이 "링크 + 한 줄 요약 + 메타"이기 때문입니다.
**요약은 LLM이 씁니다.** 앱은 그것을 모아 index.md를 조립할 뿐입니다.
300자 상한은 index.md가 비대해지는 것을 막습니다.

## 4. 세 가지 동작

### Ingest

```
파일 드롭
  → ① 텍스트 추출 + 앵커 부여                    (로컬, 무료)
  → ② ★구조 추출 — 스레드·제목트리·셀참조 등     (로컬, 무료, EXTRACTED)
  → ③ 시맨틱 캐시 조회 — 변경분만 통과            (§9.1)
  → ④ 관련 위키 페이지 선별 (FTS + 별칭 + 링크그래프)
  → ⑤ LLM CLI 실행 → ChangeSet 생성
  → ⑥ ★요점 논의 / diff 검토 화면
  → ⑦ 적용: 파일 쓰기 → index.md 재조립 → log.md 추가 → 스냅샷
```

②가 v0.3에서 새로 들어간 단계입니다. v0.2는 구조까지 전부 LLM에 맡기고 있었는데,
**문서에는 공짜로 뽑을 수 있는 구조가 많습니다.** §6.2 참조.
이 단계의 산출물은 전부 `EXTRACTED`이므로 LLM이 그 위에 추론만 얹으면 됩니다.

원문 흐름의 6단계(읽기 → 요점 논의 → 요약 → 인덱스 → 관련 페이지 → 로그)를 전부 유지합니다.
원본 1건이 페이지 10~15개를 건드릴 수 있습니다.

**두 가지 모드** (원문이 둘 다 인정):

- **감독 모드** (기본) — 한 건씩. 요약을 읽고 강조점을 지시하고 페이지별 승인
- **일괄 모드** — 여러 건을 한 번에. 검토는 마지막에 묶어서. 백로그 정리용

어느 쪽을 쓸지는 `schema/AGENTS.md`에 기록합니다.

### Query

```
질문 → index.md 먼저 읽음 → 후보 페이지 선별 (FTS5 + 링크 그래프)
     → LLM이 인용 붙여 답변 → [위키에 보관] → synthesis/ 페이지
```

**한국어 검색은 질의 길이로 전략을 가릅니다** (M0 §11 실측, 재현율·정밀도 1.000):

```
1자     거부 — 접두 매칭이 폭발해 오검색만 낸다
2자     접두 FTS + LIKE 폴백 — trigram은 3자 미만을 매칭하지 못함
3자 이상 접두 FTS + trigram FTS 합집합
```

FTS5 기본 토크나이저는 조사가 붙은 어절을 통째로 자르므로 한국어에서 **절반을 놓칩니다**
(재현율 0.524). trigram만 쓰면 2음절 단어를 전부 놓칩니다(계약·이관·검토·보안).

| 출력 형식 | v1 | 비고 |
|---|---|---|
| 마크다운 페이지 · 비교 표 | ✓ | |
| 슬라이드 덱 (Marp) | ✓ | 마크다운이라 추가 의존성 없음 |
| 차트 (matplotlib) | ✗ v2 | 사내 PC에 Python 보장 불가 |
| 캔버스 | ✗ v2 | |

### Lint

**계산 검사**(LLM 없이 앱이 판정)와 **판단 검사**(LLM 필요)를 분리합니다.
v0.2는 #3·#5를 LLM에게 물어보게 돼 있었는데, **그래프로 계산하는 쪽이 정확하고 공짜입니다.**

| # | 검사 | 방식 | 출처 |
|---|---|---|---|
| 1 | 페이지 간 모순 | LLM | 원문 |
| 2 | 새 원본이 대체한 낡은 주장 | LLM | 원문 |
| 3 | 인바운드 링크 없는 고아 페이지 | **계산** | 원문 |
| 4 | 언급되지만 자기 페이지가 없는 개념 | LLM | 원문 |
| 5 | 누락된 상호 참조 | **계산** | 원문 |
| 6 | 데이터 공백 → 찾아볼 원본 제안 | LLM | 원문(웹 검색)을 사내망에 맞게 조정 |
| 7 | 출처 없는 주장 | **계산** | 추가 |
| 8 | 깨진 앵커 (원본 교체로 번호 불일치) | **계산** | 추가 |
| 9 | **엔티티 중복 후보** | **계산** + 애매 구간만 LLM | graphify |
| 10 | `AMBIGUOUS` 주장 누적 | **계산** | 추가 |
| 11 | **한국어 AI 티** (번역투·분열문·부정 대구·연결어미 쉼표 등) | **계산** | im-not-ai |

계산 검사 7종은 즉시·무료로 돌고, LLM은 4종만 판단합니다.
모든 결과는 인제스트와 동일한 diff 검토를 거칩니다.

**#9 엔티티 중복** — v0.2의 가장 큰 구멍이었습니다. 시간이 지나면 위키가
`에이콤(주)` / `Acme` / `ACME Corp` / `에이콤`을 서로 다른 페이지 4개로 갖게 되는데,
`aliases:` 필드는 만들어 뒀지만 **그걸 채우는 절차가 없었습니다.** §8.2.

**#11 한국어 AI 티** — 근거: [`REVIEW-imnotai.md`](REVIEW-imnotai.md).
번역투("~을 가지고 있다", 이중 피동), 분열문("핵심은 ~다"), 부정 대구("A가 아니라 B" —
사람 대비 9.2배, G²=41.7), 연결어미 뒤 쉼표, 결산 lexicon 등 24개 패턴을
**LLM 없이 정규식으로** 셉니다.

**보호 구역을 반드시 마스킹합니다** — front-matter · 앵커 인용 `[^src#anchor]` ·
wikilink · 표 · 코드블록 · 헤딩 · URL. 이 안의 문자열은 탐지 대상이 아닙니다.
`summary` 필드는 index.md 조립용 메타데이터이지 산문이 아니므로 제외합니다.

검증: 심은 패턴 54건에서 **정밀도 1.000 · 재현율 1.000 · 오탐 0건**
(`spikes/korean/validate.mjs`). 오탐 0이 절대 조건입니다 — 정상 문장을 지적하면
사람이 Lint 자체를 무시하게 됩니다.

**결과는 제안일 뿐 자동 수정하지 않습니다.** 사람이 diff 검토에서 고릅니다.

## 5. index.md 와 log.md

**index.md** — 콘텐츠 지향 카탈로그. 질의 시 **가장 먼저 읽는 파일**.
LLM이 매번 다시 쓰는 대신 **앱이 front-matter의 `summary`에서 조립**합니다.
내용의 저자는 여전히 LLM이고, 조립만 결정론적이라 본문과 어긋날 수 없습니다.

```markdown
## 엔티티
- [[entities/acme-corp|에이콤(주)]] — 2026년 킥오프의 주 협력사. 계약 갱신일 불일치. `원본 4 · 2026-09-03`

**log.md** — 시간순 추가 전용. **원문이 제시한 접두사 형식 그대로:**

```markdown
## [2026-09-03] ingest | 킥오프 발표.pptx
## [2026-09-03] query  | 계약 갱신일이 언제인가

`grep "^## \[" log.md | tail -5`로 최근 이력이 나옵니다.

### 6.2 ★ 구조 추출 — LLM 없이 뽑는 관계

전부 `EXTRACTED` 신뢰도로 `<name>.structure.json`에 기록됩니다.

| 형식 | 뽑는 것 |
|---|---|
| **이메일** | **`In-Reply-To` / `References` 헤더로 스레드 트리 복원** (RFC 5322). 발신자↔수신자 그래프, 시간 순서 |
| `.xlsx` | 시트→표→열 구조, **수식의 셀 참조 = 의존 그래프**, 명명 범위 |
| `.docx` | 제목 트리(H1>H2>H3), 각주, 상호참조 필드, 주석 |
| `.pptx` | 슬라이드 순서, 제목 계층, 발표자 노트, 도형 그룹 |
| `.pdf` | 목차(북마크), 내부 링크, 각주 |
| 전사 | 화자 턴, 발언 인접 관계 |
| `.md` | `[[wikilink]]`, `[text](./other.md)` → `references` 엣지 |

**이메일 스레드 복원을 v0.2에서 완전히 놓치고 있었습니다.** 이메일은 우리 입력 형식 중
하나이고 스레드는 그 자체로 지식 구조인데, 표준 헤더로 공짜로 복원됩니다.

**xlsx 수식의 셀 참조**도 마찬가지입니다. "이 숫자가 어디서 왔나"는 업무에서 가장 자주
나오는 질문이고, 수식 그래프가 그 답입니다.

## 7. LLM CLI 어댑터 (3종)

```ts
interface AgentCli {
  id: 'claude-code' | 'gemini' | 'codex';
  detect(): Promise<{ found: boolean; path?: string; version?: string }>;
  supportsSchema: boolean;        // Claude Code·Codex true, Gemini false
  extraArgs(): string[];          // Gemini 는 '--skip-trust' (폴더 신뢰 게이트)
  run(job: { workdir: string; promptFile: string }): AsyncIterable<Chunk>;
}
```

### 7.1 쓰기 경로 (ChangeSet 생성) — 확정

1. 임시 **격리 작업 디렉터리**를 만든다
2. 이번 작업에 필요한 것만 복사한다 — `schema/AGENTS.md`, `index.md`,
   대상 `extracted/*`, 선별된 위키 페이지
3. CLI를 그 디렉터리에서 서브프로세스로 실행한다
4. **스키마를 CLI에 강제**하고 구조화된 결과를 받는다 (아래)
5. 디렉터리를 폐기한다

격리하는 이유: Vault 루트를 통째로 주면 무관한 프로젝트 문서까지 컨텍스트에 올라가고,
앱이 어떤 파일이 전달됐는지 기록·통제할 수 없습니다.

**v0.3의 "stdout에서 펜스드 ```json 블록을 회수한다"는 폐기합니다.** M0 실측 결과
Claude Code는 `--json-schema`, Codex는 `--output-schema`로 스키마를 강제할 수 있고,
응답의 **`structured_output` 키가 이미 파싱된 객체**로 옵니다. 스크래핑이 불필요합니다.

| 등급 | CLI | 처리 |
|---|---|---|
| **A — 스키마 강제** | Claude Code (`--json-schema`), Codex (`--output-schema`) | CLI가 구조를 보장. `structured_output` 직접 읽기 |
| **B — 강제 불가** | Gemini (해당 플래그 없음) | 펜스드 블록 파싱 + 앱에서 JSON Schema 검증. 실패 시 1회 재요청 |

어댑터에 `supportsSchema: boolean`을 둡니다. Gemini만 v0.3의 원래 경로를 씁니다.

**`path`에는 정규식 제약을 겁니다.** M0 실측에서 모델이 지시를 무시하고
`entities/에이콤(주).md`를 내놨습니다(우리가 지시한 `wiki/` 접두사 누락, 괄호 포함).
프롬프트 지시만으로는 부족합니다:
`^wiki/(sources|entities|concepts|synthesis)/[a-z0-9-]+\.md$`.
§9.2 `sanitizeTitle`과 이중 방어입니다.

쓰기 경로는 MCP로 대체하지 않습니다 — 에이전트가 쓰기 도구를 직접 호출하게 되면
"사람 승인 전에는 디스크에 안 쓴다"는 원칙을 지키기 어렵습니다.

### 7.1.1 ★ 비용 구조 — 배치가 필수인 이유

M0 실측 (모델 `claude-sonnet-5`, 4줄짜리 한국어 회의록 1건):

| 조건 | 턴 | cache생성 | cache읽기 | 출력 | 비용 |
|---|---|---|---|---|---|
| 기본 (파일 탐색 허용) | 8 | 34,506 | 66,087 | 2,476 | $0.176 |
| 도구 차단 + 내용 인라인 | 2 | 29,747 | 0 | 1,054 | $0.130 |
| **+ 세션 재개** | 2 | 1,713 | **29,747** | 3,605 | **$0.049** |

**문서 4줄에 $0.13이 듭니다.** 이 비용의 대부분은 우리 내용이 아니라 **CLI 자신의
시스템 프롬프트 + 도구 정의 약 3만 토큰**이고, 프로세스를 새로 띄울 때마다 cache
**생성**으로 과금됩니다. 세션을 재개하면 cache **읽기**로 바뀌어 62% 떨어집니다.

2026-09-05 재측정에서 **콜드 실행 1회의 바닥값이 $0.11338**(프롬프트 2토큰 · cache 생성
28,194)로 확인됐습니다. 다만 이 바닥은 프로세스가 아니라 **캐시가 식었을 때**의 값입니다 —
프롬프트 접두사를 바이트 단위로 고정하면 새 프로세스도 cache 읽기로 붙습니다.
5건 배치 실측이 문서당 $0.0202 입니다. 상세는 [`M2-PLAN.md`](M2-PLAN.md) §2.

**결론: 인제스트는 문서당 프로세스가 아니라 배치당 장기 세션으로 돈다.**
100건을 1건씩 처리하면 고정 오버헤드만 약 $13, 10건씩 묶으면 약 $1.3.

### 7.2 읽기 경로 (질의) — **M0 검증 후 결정**

두 안을 모두 기록해 두고 M0 결과로 확정합니다.

**안 A — 파일 복사 (현행 유지)**
쓰기 경로와 동일한 방식. 새 서브시스템 없음. 사내 정책 리스크 0.
단점: 필요할 것 같은 페이지를 **추측해서 밀어 넣어야** 하고, 안 읽힌 페이지까지 전송됩니다.

**안 B — 내장 MCP 서버**
앱에 **우리가 만든 MCP 서버를 내장**하고 CLI가 도구로 붙습니다.
`get_page` · `search` · `neighbors` · `path` 같은 읽기 전용 도구만 노출합니다.

```
[사용자 PC]  co-secondbrain.exe ─ 내장 MCP 서버   ← stdio 또는 127.0.0.1
                    ↕
             claude.exe  ─────────────────────▶  api.anthropic.com   ← 외부는 여기뿐

[사내서버]   co-hub.exe ─ MCP HTTP 엔드포인트     ← 사내 IP. 인터넷 아님
```

**외부 연동이 아닙니다.** MCP는 프로토콜이지 서비스가 아니며, 서버는 우리 실행 파일의
일부입니다. 외부로 나가는 경로는 지금과 동일하게 `CLI → api.anthropic.com` 하나뿐입니다.

오히려 **전송량이 줄어듭니다** — 에이전트가 필요한 페이지만 당겨 가므로 안 읽은 페이지는
전송되지 않습니다.

| | 안 A 파일 복사 | 안 B MCP |
|---|---|---|
| 컨텍스트 | 우리가 추측해 **밀어 넣음** | 에이전트가 **당겨 감** |
| 왕복 | 1회. 부족하면 실패 | 필요한 만큼 탐색 |
| 출력 파싱 | CLI 3종 stdout 차이 흡수 | 구조화된 도구 규약 |
| 전송량 | 밀어 넣은 만큼 전부 | 실제 읽은 것만 |
| 사내 정책 리스크 | 없음 | **MCP 등록 자체가 막혀 있을 수 있음** |

> **사내 실측 결과(2026-09-04): `cfg=OK` — 안 B를 채택합니다.**
> `--mcp-config` 경로가 사내 정책에서 열려 있음을 확인했습니다 (`M0-RESULTS.md` §8.2).

**등록 방식은 `--mcp-config`로 확정합니다.** `claude mcp add`(설정 파일에 기록)가 아니라
호출 단위로 설정 파일을 넘깁니다. 실측으로 두 경로 다 동작하지만 전자를 택하는 이유:

- 사내 PC의 기존 MCP 설정을 **건드리지 않습니다**
- `--strict-mcp-config`가 **기존 서버를 격리**합니다. 사내에 이미 등록된 HTTP MCP 서버가
  502를 내도 우리 호출에 영향이 없습니다 (사내 1차 시도에서 실제로 발생한 문제)
- 전역 설정 쓰기 권한이 필요 없어 **정책 차단 표면이 작습니다**
- Vault마다 다른 서버를 붙일 수 있습니다 (개인 금고 / CO 영역)

**사내 플러그인 로더 `mpm`이 이미 배포돼 있다는 사실이 유리한 신호입니다.**
사내에서 차단된 것은 **플러그인 마켓플레이스**이지 MCP가 아니며, mpm이 쓰는
"디렉터리 스캔 + 설정 파일 병합"은 `--mcp-config`와 같은 계열의 loose 로딩 경로입니다.
**추측이며 W1이 확인합니다** (`M0-RESULTS.md` §8.1).

### ★ Gemini는 폴더 신뢰 게이트에 걸린다

Gemini CLI는 **신뢰되지 않은 폴더에서 MCP 서버를 끕니다.** 사용자 수준 서버까지 억제합니다.

```
Warning: MCP servers are configured but disabled because this folder is untrusted.
```

§7.1이 CLI를 **격리 임시 작업 디렉터리**에서 돌리므로 항상 이 게이트에 걸립니다.

> **W3a 실측 (2026-09-05, 인증 상태). `--skip-trust` 로는 MCP 가 살아나지 않습니다.**
> 이 플래그는 대화형 확인만 건너뛸 뿐이고, 격리 디렉터리에 프로젝트 설정을 써도
> `gemini mcp list` 가 `Disabled` 로 나옵니다. 신뢰 판정이 **사용자 수준 설정**에 있어
> 고치려면 사내 PC 의 기존 설정을 건드려야 합니다. 그건 §7.2 가 `--mcp-config` 를 고른
> 이유와 정면으로 충돌하므로 하지 않습니다.
>
> **결론: Gemini 는 읽기 경로(안 B)를 쓸 수 없습니다.** 밀어 넣기(안 A)로만 가능합니다.
> `query` · `synthesis` 는 MCP 에 붙는 공급자로만 가고, 전수 스캔인 `lint.judgment` 는
> 밀어 넣기로 Gemini 에 남습니다. 상세는 [`M2-PLAN.md`](M2-PLAN.md) §12.2 · §13.

훅·프로젝트 에이전트도 같은 게이트에 걸리므로, Gemini 어댑터는 모든 호출에
`--skip-trust`를 붙입니다 — 쓰기 경로에서는 여전히 필요합니다.

### CLI별 현황

**3종 전부 지원합니다.** W1을 돌린 PC에 Codex가 없었을 뿐이고, 사내에 Codex 사용 사례가
있으므로 지원 대상에서 빼지 않습니다.

| CLI | 스키마 강제 | W1 PC | 특이사항 |
|---|---|---|---|
| Claude Code | `--json-schema` (A등급) | 2.1.260 | **기본 공급자** |
| Codex | `--output-schema` (A등급) | 미설치 | `codex exec`. **W1 PC에 없었을 뿐 지원 대상** |
| Gemini | 없음 (B등급) | 0.58.0 | `--skip-trust` 필수. B등급 경로 필요 |

**A등급 2종 · B등급 1종**입니다. 앱은 설치된 CLI를 탐지해(`detect()`) 사용 가능한 것만
목록에 올리고, 사용자가 고릅니다. 미설치 CLI는 회색 표시하고 설치 안내만 띄웁니다.

우선순위: 스키마를 강제할 수 있는 A등급(Claude Code · Codex)이 기본, Gemini는 B등급 경로
(앱에서 JSON Schema 검증 + 실패 시 1회 재요청)를 거칩니다. **B등급 경로는 M2에서 함께
구현합니다** — Gemini만 쓰는 사용자가 있을 수 있으므로 선택 기능이 아닙니다.

### 7.2.1 작업 종류별 공급자 라우팅

사내 PC에서 Claude Code·Codex는 **토큰 상한**이 있고 Gemini는 상한이 느슨합니다.
**토큰을 많이 먹지만 판단이 가벼운 작업**을 Gemini로 보냅니다.
상세는 [`PROVIDER-ROUTING.md`](PROVIDER-ROUTING.md).

| 작업 | 기본 공급자 | 자동 폴백 | 근거 |
|---|---|---|---|
| `ingest.batch` 대량 백로그 | **Gemini** | — | 토큰 최대, 반복적 |
| `lint.judgment` Lint LLM 4종 | **Gemini** | — | 전수 스캔. 어차피 다 읽으므로 밀어 넣기로 보낸다 |
| `dedup.ambiguous` 중복 애매 구간 | **Gemini** | — | 후보 제시일 뿐, 병합은 사람 승인 |
| `ingest.single` 감독 모드 | A등급 | 허용 | 사람이 옆에서 봄 |
| `query` · `synthesis` | A등급 | 허용 | 답변 품질이 곧 신뢰 |
| `schema.propose` | A등급 | **금지** | 스키마가 틀리면 이후 전부가 틀어짐 |

**갈리는 축은 "단순함"이 아니라 판단 비중입니다.** 위키는 누적 자산이라 잘못된 주장이
한 번 들어가면 그 위에 다른 페이지가 쌓입니다. 되돌리기 비용이 비대칭입니다.

**교체는 배치 단위로만 합니다.** 배치 도중 공급자를 바꾸면 세션 재개로 아끼던 고정
오버헤드(약 3만 토큰/프로세스)를 버리면서 결과 일관성만 해칩니다.

**품질 하한은 공급자와 무관하게 앱이 강제합니다** — ChangeSet 스키마·`path` 정규식·
`sanitizeTitle`·앵커 인용 존재·앵커 실재·Lint #11·`baseHash`, 그리고 사람의 diff 승인.
8개 관문 중 7개가 앱의 결정론적 검사입니다. 공급자를 바꿔 나빠질 수 있는 것은
**내용의 질**이지 **형식의 안전**이 아닙니다.

### 7.3 스키마 파일 이름

## 8. 그래프 분석 계층 (축소 도입)

### 8.1 링크 그래프 분석 — M4

우리는 **이미 그래프를 갖고 있습니다.** Obsidian 호환이라 wikilink가 그대로 간선입니다.
**새 저장 계층이 필요 없고**, 순회해서 분석만 하면 됩니다.

| 산출 | 내용 |
|---|---|
| **커뮤니티** | 위키가 실제로 어떤 하위 주제로 갈라져 있는지. **임베딩 불필요** — 링크 구조 자체가 유사도 신호 |
| **God node** | 가장 많이 연결된 개념. "모든 게 이걸 통과한다" |
| **고아 페이지** | Lint #3을 여기서 계산 |
| **누락 상호참조** | Lint #5를 여기서 계산 |
| **의외의 연결** | 서로 다른 커뮤니티에 사는 것들 사이의 링크를 **의외성 순으로 정렬.** v0.2에 없던 기능이고 "통찰"에 해당 |
| **제안 질문** | 이 위키만이 답할 수 있는 질문 4~5개 |

**M0 확정.** npm에 Leiden 구현체가 **없습니다**
(`leidenalg-js` / `@rapideditor/leiden` / `louvain-community` 전부 미존재).
`graphology-communities-louvain` 2.0.2만 유지보수됩니다.

Louvain으로 **충분합니다.** 정답을 아는 합성 위키(21노드 43간선)에서:

```
커뮤니티 탐지   3개 정답 → 3개 발견, 순도 100%, 일치율 18/18       (2ms)
God node       overview(연결 9) 정확히 1위
고아 페이지     정답 2장 → 검출 2장, 완전 일치
규모           10,000노드 100,000간선 → 65ms
```

**★ 의외의 연결은 허브를 제외해야 합니다.** 허브 노드는 모든 것과 이웃이 안 겹쳐
무조건 상위에 올라옵니다. 연결 수 상위 10%를 제외하니 **정답 포착이 1/3 → 3/3**으로
바뀌었습니다. graphify의 `--exclude-hubs`가 왜 있는지 이 측정으로 확인했습니다.

### 8.2 엔티티 중복 제거 — 단계적

**지금 넣을 것 (M4):**

M0 실측으로 **차용한 파라미터 2개를 수정**했습니다 (`M0-RESULTS.md` §4).

```
1. 정규화        NFKC + 법인격 접미사((주)/주식회사/Inc./Corp.) + ★한국어 조사 제거 + 공백·구두점
2. ★게이트       길이 ≥ 3 AND 글자당 엔트로피 ≥ 1.0
                 (graphify의 "2.5비트/글자" 단독 기준은 한국어에서 뚫림 — 길이 하한 필수)
3. Jaro-Winkler  ★임계 0.96 (graphify의 0.92는 한국어에서 오병합 3건)
                 ★자모 분해 미적용 — 적용하면 오히려 오병합이 늘어남
4. 커뮤니티 보정  같은 클러스터면 가중
5. ★사람 승인     병합은 diff 검토를 거침. 자동 병합 없음
```

측정 결과: 테스트 쌍 19개에서 **정밀도 1.000 · 재현율 0.909 · 오병합 0건.**
자동으로 못 잡는 것은 외래어 표기 흔들림(`데이타베이스`/`데이터베이스`, 0.911) 한 건.

**보류 (위키가 수백 페이지를 넘을 때):** MinHash + LSH 블로킹.
후보쌍이 적은 동안은 O(n²) Jaro-Winkler로 충분합니다. 규모가 커지면 도입합니다.

**2단계 엔트로피 게이트가 이 설계를 안전하게 만드는 부분입니다.** 짧은 이름을 자동
병합하면 서로 다른 개념이 합쳐지고, 위키에서 그건 복구가 어렵습니다.

⚠️ **테스트 쌍 19개는 작습니다.** 방향성 결과이지 검증된 수치가 아닙니다.
실제 사내 문서에서 엔티티명 100쌍 이상을 모아 재측정해야 합니다 (`M0-RESULTS.md` W5).

## 9. 운영 설계

### 9.1 시맨틱 캐시 + manifest

파일마다 **SHA256 콘텐츠 해시**로 LLM 추출 결과를 캐싱합니다. 재실행 시 변경분만 CLI에
보냅니다. **파일 이름이 바뀌면 캐시된 결과의 경로만 갱신**하고 재추출하지 않습니다.

**`manifest.json`은 성공적으로 완료됐을 때만 씁니다.** 실행 중 크래시가 나도 다음 실행의
diff가 오염되지 않습니다.

### 9.2 보안 단일 관문

모든 외부 입력이 `security.ts` 한 곳을 통과합니다.

| 함수 | 역할 |
|---|---|
| `sanitizeTitle` | **LLM이 쓴 페이지 제목이 곧 파일 이름이 됩니다.** 제어문자·경로 구분자·`..` 제거, Windows 예약어(`CON` `PRN` `NUL` `AUX` `COM1`…) 처리, 길이 상한 |
| `validateVaultPath` | 모든 쓰기 경로가 Vault 안으로 resolve되는지 |
| `validateHubUrl` | 허브 URL이 사설 IP 대역인지 |
| `capBlobSize` | 업로드 크기 상한 |

`sanitizeTitle`을 v0.2에서 놓쳤습니다. 모델이 `../../../Windows/System32/...` 같은 제목을
내면 경로 탈출입니다.

**M0 검증 완료:** 공격 문자열 14종(경로 탈출·예약어·NUL·zero-width·BiDi 위장·초장문·공백만)에서
**탈출 0건.** 구현은 `spikes/security/run.mjs`에 있고 그대로 이식합니다.

### 9.3 `.sbignore`

`.gitignore`와 같은 문법(`!` 부정 포함), 하위 디렉터리 스코프도 동일.
**추가로 제외만 할 뿐 다시 포함시키지는 않습니다.**
`sources/`를 네트워크 공유에 걸 때 필요합니다.

### 9.4 비용·토큰 상한

인제스트 작업 하나가 조용히 상한을 태우지 않도록 이중으로 막습니다.

**작업 단위**

- 작업당 최대 CLI 호출 횟수 (기본 3)
- 잘린 응답의 재귀 이분 재시도 깊이 상한 (기본 2, `0`이면 재시도 없음)
- B등급(Gemini) 스키마 검증 실패 재시도 **1회 고정**
- 상한 도달 시 실패로 처리하고 사용자에게 표시. 조용한 재시도 없음

**공급자 단위** ([`PROVIDER-ROUTING.md`](PROVIDER-ROUTING.md) §5)

- 앱이 공급자별 누적 소비를 기록합니다. Claude Code 응답의 `total_cost_usd`·`modelUsage`로
  **소비량은 정확히** 알 수 있습니다 (M0 실측 확인)
- **남은 쿼터는 응답에 없습니다.** 사내 계약 상한도 앱이 알 수 없으므로
  **사용자가 설정에서 직접 입력**합니다. 추측한 값으로 자동 전환하면 멀쩡한 쿼터를 두고
  품질을 낮추게 됩니다
- 80% 경고 → 100% 도달 시 `allowFallback` 작업만 자동 전환
- 배치 중간에 쿼터가 터지면 **이미 만든 ChangeSet은 보존**하고 남은 문서만 새 배치로
- 기본 상한은 **월 $50**입니다 (사내 기업계정 실제 예산). 화면에는 달러 대신
  `남은 배치 약 N회 · 문서 약 M건`으로 환산해 띄웁니다. 근거는 [`M2-PLAN.md`](M2-PLAN.md) §3.4
- Lint LLM 4종은 **배치로만** 실행합니다. 위키 200쪽 전수 스캔이 페이지당 프로세스면
  약 $27, 배치면 약 $11 입니다 — 월 예산의 22% 라 상시 실행할 물건이 아닙니다.
  추정 근거는 [`M2-PLAN.md`](M2-PLAN.md) §10.1 이고 계산은 `core/tokens.ts` 가 합니다.
  실행 직전에 예상 비용과 남은 예산을 보여주고 확인받습니다

### 9.5 쿼리 로그는 기본 꺼짐

로컬 쿼리 로그는 **기본 비활성**입니다. 설정에서 명시적으로 켜야 하고,
끄기 설정이 항상 우선합니다. 회사 도구로서의 기본 자세입니다.

### 9.6 한국어 작문 규칙 (`schema/AGENTS.md`)

LLM이 위키 페이지 본문·`summary`·질의 답변을 쓸 때 지킬 규칙을 스키마에 넣습니다.
Lint #11이 **사후 검출**이라면 이것은 **사전 예방**입니다.

주요 항목 (전체는 `spikes/korean/detect.mjs`의 규칙 표):

```
- "~을 가지고 있다" 금지 → 형용사·이중주어로 ("경쟁력이 강하다")
- 이중 피동 "~되어진다" 금지 → 단일 피동 또는 능동
- 분열문 "핵심은 ~다 / 중요한 것은 ~이다" 금지 → 주어-서술 직결
- 부정 대구 "A가 아니라 B" 문서당 1회 이하
- 연결어미 뒤 쉼표("~하고, ~하며,") 금지
- 결산 lexicon("결론적으로/이를 통해/요약하면") 문서당 1회 이하
- "시사하는 바가 크다/주목할 만하다" 금지 → 구체 결론으로
- 이모지 금지 (DESIGN-SYSTEM.md와 동일)
- 같은 종결어미 4문장 연속 금지
```

⚠️ **효과 미검증.** n=1 A/B에서 **S1 패턴이 줄지 않았고, 오히려 연결어미 쉼표가
1건 주입**됐습니다(`REVIEW-imnotai.md` §5). 규칙을 읽은 모델이 다시 쓰면서 그 규칙이
금지한 패턴을 새로 만든 것으로, im-not-ai가 문서화한 역주입 현상과 같습니다.

따라서 이 규칙은 **넣되 효과를 주장하지 않습니다.** M2에서 표본 20건 이상으로
재측정하고, 개선이 확인되지 않으면 제거합니다.

**재작성(윤문) 패스는 v1에서 제외합니다.** 이유 3가지는
[`REVIEW-imnotai.md`](REVIEW-imnotai.md) §6 — 우리 페이지는 산문이 아니라 구조체이고,
앵커 인용과 주장의 대응이 흐트러지며, 큰 diff는 오히려 검토를 어렵게 합니다.

## 10. CO-Hub — 사내 로컬 서버

상세는 [`HUB.md`](HUB.md).

### 10.1 허브는 멍청하다 (의도적)

허브에 **LLM이 없습니다.** 인제스트·질의·린트는 전부 각자 PC의 CLI가 수행합니다.
허브는 페이지 버전 관리, blob 보관, 이벤트 로그, 토큰 확인만 합니다.

결과: 서버에 API 키가 없고, 서버가 죽어도 로컬 미러로 계속 일하고, 구형 사내 PC 한 대면
충분합니다.

### 10.2 무엇을 동기화하는가

| 대상 | 방식 |
|---|---|
| 위키 페이지 | 전량. 작고 텍스트라 빠름 |
| index.md / log.md | 안 함. 각 클라이언트가 재생성 |
| 원본 파일(blob) | **지연 다운로드.** 인용 클릭 또는 "오프라인 고정" 시에만 |
| extracted/ | 지연. 없으면 blob 받아 로컬 재추출 |
| 이벤트 로그 | 커서 기반 pull |

### 10.3 신원과 인증

허브 관리자가 사용자별 토큰을 발급하고, 앱은 Windows 자격 증명 관리자에 보관합니다.
`updated_by`가 토큰에서 나오므로 **귀속이 위조되지 않습니다.**

### 10.4 충돌 처리 — 잠금 없음

```
PUT /v1/spaces/ACME/pages/ent-acme-corp     If-Match: 12
  → 200  적용, 버전 13
  → 409  3-way 병합 재료(base / 서버) 동봉 → 병합 화면 → 재전송
```

서버가 버전을 강제하므로 파일 잠금·heartbeat 설계가 필요 없습니다.

### 10.5 MCP 엔드포인트 (§7.2 안 B 채택 시)

허브가 동기화 API와 **같은 프로세스·같은 토큰**으로 읽기 전용 MCP HTTP 엔드포인트를
제공합니다. 동료는 로컬 설치 없이 사내 URL만 바라보면 됩니다.
사내 IP 바인딩 + 토큰 필수. 인터넷 노출 없음.

### 10.6 오프라인

로컬 미러만으로 읽기·인제스트·질의·린트가 전부 됩니다. 변경은 `.sb/sync/pending`에 쌓이고
연결되면 push합니다.

### 10.7 남는 한계

- 접근 제어 단위는 **공간(프로젝트)**. 페이지 단위 권한 없음
- 허브는 단일 장애점. 백업은 DB 파일 + blob 디렉터리 복사
- 개인 금고는 동기화·백업 대상이 아님. 앱이 백업 미설정을 경고

├─ mcp/        내장 MCP 서버(조건) ├─ sync/       기여 · 채택 · 병합
├─ changeset/  적용·충돌           └─ settings/   CLI · 허브 · 스키마 편집
├─ history/    스냅샷
├─ sync/       허브 클라이언트
├─ cache/      시맨틱 캐시
└─ security/   단일 관문
```

`contextIsolation: true`, `nodeIntegration: false`, 타입 지정 IPC 채널만 노출.
렌더러는 파일시스템에 직접 접근하지 않습니다.
**자동 업데이트·텔레메트리·크래시 리포터 없음.**
