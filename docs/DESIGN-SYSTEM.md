## 1. 원본 명세의 모순과 해소

새 명세는 세 곳에서 서로 반대되는 지시를 합니다. 셋 다 **명세 안에서** 근거를 찾아
풀었습니다.

| # | 어긋난 곳 | 해소 |
|---|---|---|
| 1 | front-matter `button-primary` 는 배경 `{colors.primary}`(크림 `#f7f4ed`) 에 글자 `{colors.neutral}`(`#eceae4`). 대비 1.06:1 로 **글자가 안 보입니다.** 산문 Components 는 "Primary Button: Accent color fill" | 산문을 따릅니다. accent 채움에 흰 글자 |
| 2 | Components 는 "Cards: Pill-shaped (9999px) corners". front-matter `rounded` 는 6·12·18 이고 Shapes 는 "Base corner radius: 6px" | 카드는 `rounded.md` 12px. 9999px 은 Do's 의 "Pill icons 9999px" 대로 **버튼·칩·아이콘에만** |
| 3 | Don'ts 는 "saturation cap: 80%". 그런데 명세가 지정한 accent `#3b82f6` 은 채도 **91%** | accent 를 `#1d4ed8`(채도 76%)로 내립니다. `#3b82f6` 은 이름 그대로 **Ring Blue** — 포커스 링에만 씁니다 |

## 2. 실측으로 정한 다섯 곳

명세의 색을 그대로 쓰면 크림 바탕에서 대비가 모자랍니다. WCAG 명암비를 계산해 고쳤고
값은 [`spikes/design/contrast.mjs`](../spikes/design/contrast.mjs) 가 매번 다시 잽니다.

| 토큰 | 명세값 | 채택값 | 이유 |
|---|---|---|---|
| `--accent` | `#3b82f6` | `#1d4ed8` | 흰 글자 대비 3.68:1 → **6.70:1**. 채도 91% → 76% |
| `--warn` | (없음) | `#946014` | GitHub 계열 `#9a6700` 은 4.43:1 로 모자라고 채도 100% |
| `--fg-faint` | `rgba(28,28,28,0.4)` | `rgba(28,28,28,0.62)` | 0.4 는 2.44:1. 캡션은 본문 글자라 4.5:1 이 필요합니다 |
| `--border-strong` | `rgba(28,28,28,0.4)` | `rgba(28,28,28,0.55)` | 아웃라인 버튼의 경계. 2.44:1 → 3.74:1 (WCAG 1.4.11) |
| 카드 그림자 | `0 2px 12px rgba(0,0,0,0.06)` | 그대로 | 다크판에서는 0.6 으로 올려야 했습니다. 밝은 바탕이라 원래 값이 맞습니다 |

## 3. 채택하지 않는 항목

`design.md` 의 아래 규칙은 **랜딩 페이지용**이며 3-pane 데스크톱 앱에 적용하지 않습니다.

- Split-screen hero (텍스트 좌 / 비주얼 우)
- Zig-zag 교차 피처 섹션과 "No 3-column equal-width" 금지
  — 3-way 병합 화면은 기준·내 것·서버 **세 칸이 같은 폭이어야** 비교가 됩니다
- `clamp(4rem, 8vw, 8rem)` 섹션 세로 간격, 1280px 중앙 정렬 컨테이너

채택하는 것은 **토큰 · 컴포넌트 · 모션** 계층입니다.

## 4. 토큰

값의 근거는 `app/src/renderer/tokens.css` 에 주석으로 같이 있습니다.
괄호 안은 `--bg-canvas` 위에서 잰 명암비입니다.

### 표면

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-canvas` | `#f7f4ed` | 창 바탕. 개인 금고 레일 |
| `--bg-surface` | `#fcfbf8` | 가운데 칸, 뷰어, 모달 판, CO 공간 레일 |
| `--bg-raised` | `#ffffff` | 카드, 입력, diff 줄 |
| `--tint` | `rgba(28,28,28,0.04)` | 호버 채움 |
| `--border` | `#eceae4` | 1px 경계선 |
| `--border-strong` | `rgba(28,28,28,0.55)` | 아웃라인 버튼 (3.74:1) |

다크판과 반대로 **위로 올라올수록 밝아집니다.** 밝은 바탕에서 그림자만으로 층을 만들면
경계가 흐려집니다.

### 글자

회색은 전부 `#1c1c1c` 의 투명도입니다 (명세 Elevation & Depth).

| 토큰 | 값 | 대비 | 용도 |
|---|---|---|---|
| `--fg` | `#1c1c1c` | 15.51:1 | 본문 |
| `--fg-muted` | `#5f5f5d` | 5.83:1 | 캡션, 메타데이터 |
| `--fg-faint` | `rgba(28,28,28,0.62)` | 4.64:1 | 앵커, 조각 수 같은 보조 수치 |

### 강조와 의미

| 토큰 | 값 | 대비 | 채도 | 용도 |
|---|---|---|---|---|
| `--accent` · `--info` | `#1d4ed8` | 6.10:1 | 76% | 기본 버튼 채움, 인용 링크 |
| `--ring` | `#3b82f6` | 3.35:1 | — | 포커스 링 (비텍스트 3:1) |
| `--ok` | `#1a7f37` | 4.62:1 | 66% | 인제스트 성공, 추가된 줄 |
| `--warn` | `#946014` | 4.85:1 | 76% | 낮은 confidence, 낡은 주장 |
| `--danger` | `#cf222e` | 4.88:1 | 72% | 모순, 충돌, 추출 실패 |

`--ok-wash` `--danger-wash` `--info-wash` 는 diff 줄과 인용 블록의 배경입니다.
**색만으로 구분하지 않습니다** — 왼쪽 3px 막대를 항상 같이 씁니다 (색각 이상 대응).

다크 모드는 v1 범위 밖입니다. `design.md` 가 `Light/Dark: ✓ Full / ✗ Not Recommended`
로 라이트 전용을 명시합니다.

## 5. 타이포그래피

**폰트 파일을 번들하지 않습니다.** 명세가 `system-ui` 를 지정했고 Windows 11 의
Segoe UI Variable 이 바로 명세가 말하는 휴머니스트 가변 폰트입니다. 사내망에서 Google Fonts
CDN 을 못 쓰는 문제가 여기서 사라집니다.

```
--font: 'Segoe UI Variable Text', 'Segoe UI', system-ui, 'Malgun Gothic',
        'Apple SD Gothic Neo', sans-serif
--mono: 'JetBrains Mono', 'Cascadia Mono', 'D2Coding', ui-monospace, monospace
```

한글 폴백이 필수입니다. Segoe UI Variable 은 한글 글리프를 포함하지 않습니다.

본문 굵기는 명세대로 **480** 입니다. 가변 폰트에서는 400 과 500 사이가 잡히고 가변이
아닌 폰트에서는 CSS 폰트 매칭 규칙이 400 을 고릅니다 — 둘 다 안전합니다.

| 역할 | 크기 / 굵기 | 자간 |
|---|---|---|
| 화면 제목 | 1.5rem / 700 | -0.02em |
| 섹션 제목 | 1.125rem / 600 | -0.02em |
| 본문 | 0.9375rem / 480, line-height 1.6 | 0 |
| UI 라벨 | 0.875rem / 500 | 0.01em |
| 캡션·메타 | 0.8125rem / 480 | 0 |
| 모노 | 0.8125rem / 400 | 0 |

자간은 **큰 제목에만** 겁니다. 다크판에서는 -0.06em 이었는데 크림 바탕에서는 굵은 제목이
눌려 보여 -0.02em 으로 줄였습니다. 본문에 걸면 한글 가독성이 무너집니다.

위키 본문 열 폭은 `72ch` 상한 (`design.md` Body 규칙).

## 6. 간격 · 형태

- 기본 단위 **8px**. 4px 는 아이콘·라벨 등 조밀한 곳에만.
- 모서리: 입력 6px (`rounded.sm`) · 카드 12px (`rounded.md`) · 모달 18px (`rounded.lg`) ·
  **버튼과 칩과 아이콘은 9999px**.
- 카드는 1px 경계선 + `0 2px 12px rgba(0,0,0,0.06)`. 떠 있는 판은 `0 8px 28px rgba(28,28,28,0.12)`.
- 버튼에는 안쪽 그림자 `rgba(255,255,255,0.2) 0 0.5px inset, rgba(0,0,0,0.2) 0 0 0.5px inset`
  (명세 Elevation & Depth).

## 7. 모션

`design.md` 의 규칙에 emilkowalski/skills 의 판단을 얹었습니다. 두 출처가 어긋나는 곳은
없었습니다. 후자가 더 구체적입니다.

- **커스텀 이징을 씁니다.** 브라우저 기본 이징은 약합니다.
  `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)` · `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`.
- **`ease-in` 을 UI 에 쓰지 않습니다.** 시작이 느려 같은 시간이어도 굼떠 보입니다.
- **`transition: all` 을 쓰지 않습니다.** 바뀌는 속성만 적습니다.
- 지속 시간은 UI 에서 300ms 아래. 눌림 되먹임 160ms · 진입 300ms · 호버 200ms.
- 진입은 fade + translateY(12px→0) + scale(0.99→1).
  **`scale(0)` 에서 시작하지 않습니다** — 없던 데서 튀어나온 것처럼 보입니다.
- 목록은 40ms 스태거. 다섯 번째부터는 지연을 늘리지 않습니다.
- 누르면 `scale(0.97)`. 인터페이스가 듣고 있다는 신호입니다.
- 호버는 `@media (hover: hover) and (pointer: fine)` 안에서만 겁니다.
  터치 기기는 탭에 호버가 붙어 오작동합니다.
- `transform` 과 `opacity` 만 애니메이션합니다 (레이아웃 유발 속성 금지).
- **스피너 금지 → 스켈레톤 셔머.** 인제스트·질의 대기 UI 전부 스켈레톤.
- `prefers-reduced-motion: reduce` 에서는 **이동을 없애고 전환은 남깁니다.**
  전부 끄면 상태 변화를 못 따라갑니다.

## 8. 컴포넌트 규칙

- **기본 버튼**: `--accent` 채움, 흰 글자, weight 600, 알약 모양, 안쪽 그림자.
  호버 시 `--accent-hover`, 누름 시 `scale(0.97)`. 외곽 글로우 금지.
- **보조 버튼**: 1.5px `--border-strong` 아웃라인, 배경 없음. 호버 시 `--tint` 채움.
- **입력**: 라벨을 입력 위에. floating label 금지. 포커스 링 `--ring` 2px, offset 2px.
  오류 문구는 아래에 `--danger`.
- **내비게이션**: 활성 항목에 `--accent` 인디케이터, weight 500.
- **빈 상태**: 아이콘 + 설명 + 액션 버튼 구성.
- **이모지 금지.** 아이콘은 `app/src/renderer/icons.tsx` 의 열 개뿐입니다 —
  24 격자, 선 굵기 1.75, 둥근 끝. 라이브러리를 붙이지 않습니다 (사내망에서 CDN 불가,
  필요한 것이 열 개).

## 9. 이 앱 고유의 컴포넌트

`design.md` 에 없어 새로 정의합니다.

- **Diff 검토 카드** — 인제스트 승인 화면의 핵심. 페이지당 카드 1장, 좌: 현재 / 우: 제안.
  추가 줄은 `--ok` 왼쪽 막대 + `--ok-wash`, 삭제는 `--danger` 쪽. 카드 하단에 승인 / 거부 /
  편집 후 승인. ChangeSet 의 `discussion` 필드는 카드 위에 인용 블록으로 표시.
- **인용 칩** — `[^src-kickoff#slide-12]` 를 모노 인라인 칩으로 렌더. 호버 시 원문 발췌 툴팁,
  클릭 시 원문 뷰어의 해당 슬라이드·페이지·셀로 점프. 앵커가 깨진 칩은 `--danger` 취소선.
- **Confidence 배지** — `high` 는 배지 없음(기본), `medium` `--warn`, `low` `--danger` 외곽선.
  기본값에 배지를 안 붙여야 낮은 신뢰도가 눈에 띕니다.
- **동기화 상태 표시** — 좌측 레일. 4가지 상태만: `동기화` / `동기화 · 보낼 것 N` /
  `충돌 N건`(`--warn`) / `허브 연결`. 진행 중에는 스켈레톤 셔머.
- **Contribute 검토 화면** — 개인 → CO 유출 방지 장치. 공유될 페이지 전문을 그대로 보여주고,
  개인 전용 링크가 포함돼 있으면 `--danger` 로 표시한 뒤 **push 버튼을 비활성화**합니다.
- **Adopt 배지** — 채택한 페이지 상단에 `co://ACME/... @v12에서 채택` 모노 배지.
  원본이 갱신되면 `--warn` 으로 바뀌고 [갱신 반영] 버튼이 붙습니다.
- **3-way 병합 화면** — 3열. 좌: 공통 기준(v12), 중: 서버, 우: 내 것.
  줄 단위로 어느 쪽을 채택할지 선택하고, 직접 편집도 가능.
- **오류 기록 패널** — 좌측 레일 맨 아래 버튼에서 엽니다. 오류가 없으면 `--fg-faint` 로
  가라앉고 있으면 `--danger` 로 건수를 답니다. **상시 빨간 배지는 곧 무시됩니다.**
  패널에서 [복사] · [파일로] · [비우기]. 자세한 것은 §12.
- **열람 등급 배지** — 원본 목록과 페이지에 붙는 알약. `사내` 는 기본값이라 `--fg-faint`
  로 가라앉히고 `기밀` · `제한` 만 `--danger` 로 띄웁니다. **기본값에 배지를 크게 붙이면
  기밀이 안 보입니다** — Confidence 배지와 같은 규칙입니다. `공개` 는 `--ok`.
- **받은 편지함** — 좌측 레일 맨 위. `00_INBOX/` 가 비어 있으면 **아무것도 그리지
  않습니다.** 늘 떠 있는 빈 구역은 곧 안 보이게 됩니다. 파일마다 `대기` · `처리` · `불가`
  세 상태만 보여주고 여섯 건까지만 늘어놓습니다.
- **등급 선택기** — [문서 추가] 위에 둡니다. 넣고 나서 고치게 하면 아무도 안 고칩니다.
- **설정 패널** — [문서 추가] 옆 톱니 버튼. 앱 판 · 금고 이름과 폴더 경로 · 쓸 CLI ·
  [금고 닫고 첫 화면으로] 를 한 화면에 둡니다. 금고 경로는 **여기서만** 보여줍니다 —
  오류 기록에는 안 들어갑니다(§12). 사람이 직접 보는 화면과 통째로 복사되는 기록은 다릅니다.
  CLI 는 라디오 한 줄에 근거를 같이 답니다. 이름만 있으면 무엇이 다른지 모릅니다.
- **내 맥락 패널** — 세 문항의 여러 줄 입력. 무엇을 적어야 하는지는 칸 위 안내 문구가
  말합니다. 저장 버튼은 **고친 것이 있을 때만** 살아납니다. 정본이 금고 안 파일이라는 것과
  동기화가 올리지 않는다는 것을 패널 맨 위에 적습니다 (PLAN.md §3.3).
- **빈 상태** — 아이콘 + 설명 + 액션 버튼 (`design.md` 규칙).

## 10. 개인 / CO 공간 구분 (시각 규칙)

두 공간을 **한눈에 구별하지 못하면 사고가 납니다.** 개인 메모를 CO 에 올리거나 반대로
착각하는 것을 막는 것이 이 규칙의 유일한 목적입니다.

| 요소 | 개인 공간 | CO 공간 |
|---|---|---|
| 좌측 레일 배경 | `--bg-canvas` (`#f7f4ed`) | `--bg-surface` (`#fcfbf8`) |
| 공간 이름 앞 알약 | `lock` 아이콘 + `개인` | `users` 아이콘 + `CO` |
| 레일 머리 아래 1px 선 | `--border` | `--info` (`#1d4ed8`) |
| 페이지 제목 앞 접두 | 없음 | `ACME ·` 모노 폰트 |

CO 공간에서만 위쪽에 얇은 파란 선이 그어집니다. 색상 하나로 상태를 구분하지 않도록
아이콘과 접두 텍스트를 함께 씁니다(색각 이상 대응).

## 11. 앱 아이콘

원본은 [`design/icon/co_second_brain_v2.png`](../design/icon/co_second_brain_v2.png) 입니다.
**다시 그리지 않습니다.** `spikes/icon/render.mjs` 가 하는 일은 두 가지뿐입니다 — 판 바깥
배경을 투명으로 바꾸고 크기를 줄입니다.

배경은 색을 키로 잡지 않고 **네 모서리에서 시작하는 채움**으로 지웁니다. 판 안쪽과 바깥
배경이 둘 다 거의 흰색이라 색으로 자르면 판 속까지 뚫립니다. 이어진 영역만 지우면 판
테두리에서 멈춥니다. 자가 검사가 그 두 가지를 같이 봅니다 — 모서리가 투명한가, 판 속이
남아 있는가.

같은 저장소에 있는 `co_second_brain_v2.svg` 는 원본을 흑백으로 추적한 것이라 크림 판과
회색 노드가 빠집니다. 자산 생성에는 PNG 를 씁니다.

## 12. 오류 기록의 시각 규칙

기록의 목적지는 **클립보드**입니다. 사내 문서를 다루는 앱에서 클립보드는 반출 경로이므로
`core/log.ts` 가 적재 시점에 파일 이름과 토큰을 지웁니다 — 경로는 `<파일 12자>.pptx`
처럼 확장자와 글자 수만 남습니다.

- 패널 맨 위에 **무엇이 지워졌는지 한 줄로 적습니다.** 안 적으면 사람이 원문이 나갔다고
  의심하거나, 반대로 나가지 않았다고 오해합니다.
- 최근 것이 위입니다. 기본은 `오류만` 보기입니다.
- 등급은 알약 배지로 `오류`(`--danger`) · `경고`(`--warn`) · `정보`(`--fg-faint`).
- 스택은 접지 않고 모노 블록으로 그대로 둡니다. 접으면 복사 전에 확인을 안 합니다.
