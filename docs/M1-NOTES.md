## 1. 엔티티 중복 — 커뮤니티 가중치를 넣었다가 뺐다

같은 커뮤니티에 속한 두 페이지의 유사도에 `+0.02` 를 더하는 가중치를 처음에 넣었다.
근거 없이 넣은 값이었고, M0 §4 의 음성 쌍(절대 병합되면 안 되는 쌍)으로 재보니 오병합이 생긴다.

| 쌍 | 유사도 | +0.02 | 임계 0.96 |
|---|---|---|---|
| `구매팀` \| `구매팀장` | 0.942 | **0.962** | **오병합** |
| `에이콤` \| `에이스콤` | 0.933 | 0.953 | 안전 |
| `2026년 계획` \| `2027년 계획` | 0.933 | 0.953 | 안전 |
| `서울지사` \| `서울지점` | 0.883 | 0.903 | 안전 |
| `개발1팀` \| `개발2팀` | 0.867 | 0.887 | 안전 |
| `김철수` \| `김영수` | 0.800 | 0.820 | 안전 |
| `에이콤` \| `베이콤` | 0.778 | 0.798 | 안전 |
| `계약 갱신` \| `계약 해지` | 0.733 | 0.753 | 안전 |

여유가 0.018 밖에 없는 쌍이 하나만 있어도 가중치는 쓸 수 없다. 위키에서 오병합은 복구가 어렵고,
**오탐 0 이 절대 조건**이다(§9). 커뮤니티 일치는 후보에 `sameCommunity` 플래그로 표시만 하고
판정에는 쓰지 않는다. 사람이 diff 검토에서 참고한다.

`app/test/lint.test.ts` 가 이 수치를 그대로 잠가 둔다 — 나중에 누가 다시 가중치를 넣으면 테스트가 깨진다.

## 2. 허브 제외는 노드가 적으면 동작하지 않는다

`findSurprising` 의 허브 임계는 M0 §5.3 과 같은 상위 백분위(0.9)다.
`degrees[floor(n * 0.9)]` 를 넘는 노드만 허브인데, **n 이 작으면 이 인덱스가 최댓값 근처**라
아무도 허브가 되지 않는다.

- n=8, 허브 연결 2 → 허브 제외 0개. 허브가 만든 간선이 후보에 그대로 남는다
- n=17, 허브 연결 16 → 허브 1개 제외. 진짜 다리(`a0-b0`)가 의외성 0.86 으로 1위

위키가 커지기 전에는 "의외의 연결"이 허브 간선으로 오염된다는 뜻이다. 지금은 고치지 않는다 —
페이지가 20개도 안 되는 위키에서 의외의 연결을 뽑는 것 자체가 의미가 없다.
**실사용에서 이 화면이 언제부터 쓸모 있는지는 아직 모른다.** W4(실제 사내 문서)에서 본다.

## 3. front-matter 를 읽고 그대로 쓰면 바이트가 달랐다

`parsePage` 가 닫는 `---` 뒤 줄바꿈까지 먹어서, 읽고 다시 쓸 때마다 본문 첫 줄이 바뀌었다.
사람이 diff 로 승인하는 구조에서 이 잡음은 곧 비용이다. 정규식에서 줄바꿈을 본문에 남기도록 고쳤다.
`app/test/page.test.ts` 가 바이트 동일성을 검사한다.

## 4. graphology 는 CJS 라 NodeNext 에서 기본 임포트가 깨진다

타입 선언은 `export default class Graph` 인데 패키지는 CJS(`module.exports = Graph`)다.
`module: NodeNext` 에서 `import Graph from 'graphology'` 는 네임스페이스로 잡혀
`new Graph()` 가 타입 오류가 된다. `esModuleInterop` 을 켜도 그대로다(확인함).

런타임의 실제 모양을 확인하고 거기 맞췄다.

| 모듈 | 런타임 | 쓰는 법 |
|---|---|---|
| `graphology` | 이름 내보내기 `UndirectedGraph` 가 실제 클래스 | `import { UndirectedGraph }` |
| `graphology-communities-louvain` | `module.exports = fn` — 기본 임포트가 함수 | 기본 임포트 + 시그니처 캐스트 |

`@kenjiuno/msgreader` 때와 같은 유형이다(M0 §3). **CJS 패키지는 타입 선언이 아니라 런타임을 보고 맞춘다.**
