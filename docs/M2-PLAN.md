# M2 구현 방법 재검토 — 계정 분리와 월 $50 예산

작성 2026-09-05. [`PLAN.md`](PLAN.md) §7.1.1 · §9.4 · §12 · §13 을 고치게 만든 측정이다.

## 0. 새로 들어온 제약 두 가지

1. 개발에 쓰는 Claude Code 계정을 사내 PC에서 쓸 수 없다. 사내는 별도 기업계정이다.
2. **사내 기업계정의 토큰 예산이 월 $50이다.** 이건 개발 예산이 아니다. **앱이 실사용 중
   태우는 예산이다.** 그래서 제품 설계 제약이 된다.

기존 M2 계획은 "CLI가 사내 PC에만 있으므로 어댑터도 사내에서 만든다"를 전제했다.
측정해 보니 그 전제가 틀렸다.

## 1. 실측 — 개발 컨테이너에 CLI 3종이 다 있다

| CLI | 버전 | 스키마 강제 | 인증 |
|---|---|---|---|
| `claude` | 2.1.261 | `--json-schema` — 실행해서 확인 | **됨** |
| `gemini` | 0.58.0 | 없음 (B등급 확정, `PLAN.md` §7.1 과 일치) | 안 됨 — `GEMINI_API_KEY` 필요 |
| `codex` | 0.153.2 | `--output-schema` 플래그 존재 | 미확인 — `--skip-git-repo-check` 선행 필요 |

A등급 경로 실행 결과:

```
claude -p "2+3은? n에 숫자만." --json-schema '{...}' --output-format json \
       --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch Task
→ structured_output: {"n":5}      num_turns=2      is_error=false
```

`PLAN.md` §7.1 의 A등급 경로가 **사내 PC 없이 이 컨테이너에서 그대로 돈다.**

### 1.1 주의 — 서브프로세스가 부모 세션 id를 물고 나온다

위 실행의 응답 `session_id` 가 부모 세션의 id와 같았다. 환경변수
`CLAUDE_CODE_SESSION_ID` 가 상속되기 때문이다. Electron 앱에서는 이 변수가 없으므로
제품에서는 생기지 않는다. 다만 **개발 중 `--resume` 배치를 시험할 때 부모 세션과 충돌**하므로
어댑터는 자식 프로세스 환경에서 이 변수를 지우고 띄운다.

### 1.2 프롬프트는 stdin 으로 넘어간다. 스키마는 안 된다

사내 PC 는 Windows 다. `spawn` 이 `.cmd` 를 띄우려면 shell 을 거쳐야 하고 그러면 인용부호가
위험해진다. 그래서 무엇을 argv 로 보내야 하는지 재 봤다.

| 항목 | 결과 |
|---|---|
| `claude -p` 를 인자 없이 두고 프롬프트를 stdin 으로 | **동작** — 3건 전부 관문 통과 |
| `gemini` 를 `-p` 없이 두고 프롬프트를 stdin 으로 | **동작** — 3건 전부 관문 통과 |
| `claude --json-schema` 에 파일 경로 | **거부** — `is not valid JSON: Unexpected identifier` |

프롬프트는 stdin 으로 빠지지만 **스키마 약 1.5KB 는 argv 로 나가야 한다.** 그 안에 `^` `|`
`\` 같은 cmd 메타문자가 들어 있다. Windows 에서 이게 통과하는지는 확인하지 못했다.
회수 스크립트가 찾은 실행 파일 경로와 shell 경유 여부를 보고에 남기게 해 뒀다.

## 2. 실측 — 비용을 가르는 것은 프로세스 수가 아니라 프롬프트 접두사다

**이 절은 오전에 쓴 내용을 정정한다.** 처음에는 "프로세스를 새로 띄울 때마다 cache
생성으로 과금된다"고 적었다. 배치를 실제로 돌려 보니 절반만 맞았다.

### 2.1 콜드 실행 세 번

| # | 조건 | cache 생성 | cache 읽기 | 출력 | 비용 |
|---|---|---|---|---|---|
| A | 프롬프트 2토큰, 규약 파일 없음 | 28,194 | 0 | 60 | **$0.11338** |
| B | 규약 파일 + ChangeSet 스키마, 원본 1건 | 28,888 | 0 | 1,506 | **$0.13062** |
| C | B와 **같은 규약 파일·같은 스키마**, 새 프로세스 | 5,853 | 22,873 | 733 | **$0.03530** |

A와 B는 10분 간격이었는데도 둘 다 cache 읽기가 0이다. B와 C는 새 프로세스인데 C가
22,873 토큰을 읽었다. 프로세스를 새로 띄웠는지는 상관이 없다. **프롬프트 접두사가 바이트
단위로 같은지**가 가른다.
접두사는 CLI 시스템 프롬프트와 도구 정의에 더해 cwd 의 규약 파일과 우리가 물린 스키마까지를 묶은 덩어리이고 응답의 `ephemeral_1h_input_tokens` 필드로 보아 이 캐시는 1시간짜리다 (TTL 경계는 직접 재지 않았다).

**설계 규칙이 하나 나온다. 인제스트 프롬프트의 접두사를 고정한다.** 문서마다 달라지는
내용을 앞에 두면 배치 전체의 캐시가 깨진다. 규약 파일과 스키마는 배치 내내 같은 바이트여야
한다.

### 2.2 5건 배치 실측

같은 규약 파일과 스키마로 원본 5건을 한 세션에 이어 붙였다 (`--resume`). 전건이
`changeset.ts` 의 관문을 통과했다.

| # | 비용 | cache 생성 | cache 읽기 | 출력 |
|---|---|---|---|---|
| 1 | $0.0353 | 5,853 | 22,873 | 733 |
| 2 | $0.0171 | 1,164 | 28,726 | 670 |
| 3 | $0.0160 | 896 | 29,890 | 640 |
| 4 | $0.0160 | 868 | 30,786 | 638 |
| 5 | $0.0167 | 876 | 31,654 | 690 |

**합계 $0.1011, 문서당 $0.0202, 61초.**

문맥이 쌓이면 문서당 비용이 오를 것이라 예상했는데 그렇지 않았다. cache 읽기가 문서당
약 900토큰씩 늘지만 읽기 단가가 낮아 비용은 평평하다. 표본 5건이라 더 긴 배치에서도
평평한지는 모른다. 긴 배치의 실제 한계로는 비용보다 컨텍스트 창과 품질이 먼저 올 것이다.

### 2.3 무엇이 프로세스를 건너 캐시되는가

2026-09-05 회수 스크립트 실행(`spikes/cli/record.mjs`)에서 §2.1 의 그림이 더 선명해졌다.
같은 규약 파일과 같은 스키마로 원본 3건을 **각각 새 프로세스**로 돌렸다.

| 사례 | cache 생성 | cache 읽기 | 비용 |
|---|---|---|---|
| kickoff | 6,303 | 22,873 | $0.0698 |
| contract | 6,243 | 22,873 | $0.0365 |
| cost | 6,245 | 22,873 | $0.0378 |

**읽기 22,873 이 세 번 다 똑같다.** 이건 CLI 자기 시스템 프롬프트이고 프로세스가 달라도
캐시로 붙는다. 반면 우리 규약 파일과 스키마에 해당하는 약 6,250 은 **매 콜드 프로세스마다
생성으로 다시 과금된다.**

§2.2 배치에서 2번째부터 생성이 900 대로 떨어진 이유가 여기 있다. `--resume` 이 캐시해 주는
것은 **우리 내용**이고 CLI 자기 접두사는 재개 없이도 붙는다. 두 절약이 겹쳐야 문서당
$0.02 가 나온다.

### 2.3 월 $50 환산

| 조건 | 문서당 | 월 처리량 |
|---|---|---|
| 콜드 캐시 · 문서당 프로세스 | $0.130 | 약 385건 |
| 접두사 고정 · 5건 배치 (실측) | $0.0202 | 약 2,475건 |

**6.4배 차이다.** 오전에 적은 "배치가 요건"이라는 결론은 그대로 서고 이유가 하나 늘었다.
배치는 세션 재개로도 아끼고 **접두사 캐시를 살려 두는 것으로도** 아낀다.

## 3. 바뀌는 것

### 3.1 사내 PC의 역할을 녹화로 줄인다

| 경로 | 어디서 만드나 | 사내 PC 몫 |
|---|---|---|
| A등급 (Claude Code) | **이 컨테이너에서 끝까지** | W2 — Windows spawn·경로·인용부호 확인 |
| B등급 (Gemini) | 인터페이스와 파서까지 여기서 | W3 — 실호출 **응답 녹화** |
| Codex | 인터페이스와 파서까지 여기서 | W3b — 실호출 **응답 녹화** |

사내 PC에서 개발 루프를 돌지 않는다. `spikes/cli/record.mjs` 를 한 번 실행해 3종 CLI의
원시 응답을 `spikes/fixtures/cli/*.json` 으로 떨구고 저장소에 커밋하면, 나머지 파서 작업과
회귀 테스트는 여기서 끝난다. **왕복 1회로 줄인다.**

### 3.2 배치 세션 재개는 M2 기본 경로다

M2 완료 기준에 비용 조건을 넣는다. "원본 1건이 끝까지 돎"만으로는 예산을 지킬 수 없다.
새 기준: **5건 이상 배치가 세션 재개로 돌고 문서당 비용이 $0.03 미만.**
2026-09-05 실측에서 5건 배치가 문서당 $0.0202 였다 (§2.2).

### 3.3 Lint LLM 4종은 배치 전용이다

§7.2.1 은 Lint LLM 4종을 Gemini로 보낸다. 사내에서 Gemini를 쓰지 못하면 이 부하가 전부
$50 예산으로 온다. 위키 200쪽 전수 스캔을 페이지당 프로세스로 돌리면 약 $22.6 이고
배치로 묶으면 약 $4 다 (§2.2 실측 문서당 $0.0202 기준).

**처음에는 비용을 근거로 기본 비활성을 제안했는데 측정이 그 근거를 지웠다.** $4 는 월 예산의
8% 라 상시 실행을 막을 이유가 되지 못한다. 남는 이유는 결과를 사람이 전부 검토해야 한다는
쪽이다. 그래서 규칙을 이렇게 줄인다.

- 배치 세션으로만 실행한다. 페이지당 프로세스 금지
- 사용자가 실행 시점을 고른다. 저장할 때마다 자동으로 돌리지 않는다
- 실행 직전에 **예상 비용과 남은 예산을 보여주고 확인받는다**

### 3.4 지출 계량기를 남은 문서 수로 보여준다

§9.4 의 "사용자가 상한을 직접 입력한다"는 유지하되 기본값을 월 $50 으로 둔다.
`total_cost_usd` 와 `modelUsage` 가 응답에 정확히 오므로(위 §2 실측) 추정이 아니다.
화면에는 `남은 배치 약 N회 · 문서 약 M건` 으로 환산해 띄운다. 사용자는 문서 단위로 생각한다.

## 5. 확실하지 않은 것

- Codex 인증 상태를 확인하지 않았다. 사내 PC 녹화에서 같이 본다
- Gemini B등급 응답의 실제 형태를 아직 못 봤다. 파서는 합성 입력으로 먼저 만들고 녹화가
  오면 회귀 테스트로 고정한다
- 월 $50 환산은 한 줄짜리 합성 원본으로 잰 것이다. 실제 사내 문서는 원본 텍스트가 훨씬
  길어 변동분이 늘어난다. 실제 문서로 재측정할 항목이다
- 배치 5건까지만 재봤다. 20건·50건에서도 문서당 비용이 평평한지는 모른다
- 접두사 캐시의 TTL 경계를 재지 않았다. 사용자가 한참 쉬었다 돌아오면 콜드 가격을 다시 낸다

## 6. 구현에서 나온 것

### 6.1 렌더러가 core 를 그대로 부르면 번들이 깨진다

검토 화면은 체크박스를 누를 때마다 승인 가능 여부를 다시 판정해야 해서 판정 함수를
렌더러에서 부른다. 그런데 `core/review.ts` 는 디스크를 읽으려고 `node:fs` 를 쓰고 그 안에서
`page.ts` 가 `node:crypto` 를 끌어온다. vite 빌드가 `"createHash" is not exported by
"__vite-browser-external"` 로 죽었다.

순수 판정만 `core/approve.ts` 로 갈랐다. 이 파일은 값 임포트로 Node 모듈을 쓰지 않는다.
번들 모듈 수가 109개에서 32개로 줄었다. 같은 실수가 다시 나지 않게 소스에 `node:` 값
임포트가 있는지 테스트로 잠갔다.

### 6.2 관문 8 실측

합성 킥오프 pptx 한 건을 인제스트해서 끝까지 돌렸다.

- 변경안 3건(`wiki/overview.md` · `wiki/entities/에이콤.md` · `wiki/sources/kickoff.md`)
- 관문 위반 0, 충돌 0, 깨진 인용 0
- **검토를 두 번 해도 `wiki/entities/` 가 비어 있었다.** 승인해야 파일이 생겼다
- 적용 뒤 `index.md` 가 다시 조립되고 스냅샷이 남았다

### 6.3 아직 없는 것

- **Electron 진입점(`main.ts`)이 없다.** IPC 계약과 `Store` 메서드까지 만들었고 `ipcMain`
  핸들러 등록은 창을 띄우는 코드와 함께 M7 에서 붙는다. 지금은 core 를 직접 불러 검증한다
- **"편집 후 승인"** — `DESIGN-SYSTEM.md` 가 카드 하단에 두라고 한 세 번째 버튼이다.
  편집기가 필요해 별도로 잡는다. 지금은 승인과 보류만 있다
- `.tsx` 는 타입체크와 vite 빌드로만 검증한다. Node 의 타입 제거는 JSX 를 다루지 못해
  테스트 러너에서 못 돈다. 그래서 판정 로직을 전부 core 로 내렸다
