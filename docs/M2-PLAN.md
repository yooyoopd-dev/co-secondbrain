# M2 구현 방법 재검토 — 계정 분리와 월 $50 예산

작성 2026-09-05. [`PLAN.md`](PLAN.md) §7.1.1 · §9.4 · §12 · §13 을 고치게 만든 측정이다.

## 0. 새로 들어온 제약 두 가지

1. 개발에 쓰는 Claude Code 계정을 사내 PC에서 쓸 수 없다. 사내는 별도 기업계정이다.
2. **사내 기업계정의 토큰 예산이 월 $50이다.** 이건 개발 예산이 아니다. **앱이 실사용 중
   태우는 예산이다.** 그래서 제품 설계 제약이 된다.

기존 M2 계획은 "CLI가 사내 PC에만 있으므로 어댑터도 사내에서 만든다"를 전제했다.
측정해 보니 그 전제가 틀렸다.

## 1. 실측 — 개발 컨테이너에 CLI 3종이 다 있다

| CLI | 버전 | 스키마 강제 | 인증 |
|---|---|---|---|
| `claude` | 2.1.261 | `--json-schema` — 실행해서 확인 | **됨** |
| `gemini` | 0.58.0 | 없음 (B등급 확정, `PLAN.md` §7.1 과 일치) | 안 됨 — `GEMINI_API_KEY` 필요 |
| `codex` | 0.153.2 | `--output-schema` 플래그 존재 | 미확인 — `--skip-git-repo-check` 선행 필요 |

A등급 경로 실행 결과:

```
claude -p "2+3은? n에 숫자만." --json-schema '{...}' --output-format json \
       --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch Task
→ structured_output: {"n":5}      num_turns=2      is_error=false
```

`PLAN.md` §7.1 의 A등급 경로가 **사내 PC 없이 이 컨테이너에서 그대로 돈다.**

### 1.1 주의 — 서브프로세스가 부모 세션 id를 물고 나온다

위 실행의 응답 `session_id` 가 부모 세션의 id와 같았다. 환경변수
`CLAUDE_CODE_SESSION_ID` 가 상속되기 때문이다. Electron 앱에서는 이 변수가 없으므로
제품에서는 생기지 않는다. 다만 **개발 중 `--resume` 배치를 시험할 때 부모 세션과 충돌**하므로
어댑터는 자식 프로세스 환경에서 이 변수를 지우고 띄운다.

### 1.2 프롬프트는 stdin 으로 넘어간다. 스키마는 안 된다

사내 PC 는 Windows 다. `spawn` 이 `.cmd` 를 띄우려면 shell 을 거쳐야 하고 그러면 인용부호가
위험해진다. 그래서 무엇을 argv 로 보내야 하는지 재 봤다.

| 항목 | 결과 |
|---|---|
| `claude -p` 를 인자 없이 두고 프롬프트를 stdin 으로 | **동작** — 3건 전부 관문 통과 |
| `gemini` 를 `-p` 없이 두고 프롬프트를 stdin 으로 | **동작** — 3건 전부 관문 통과 |
| `claude --json-schema` 에 파일 경로 | **거부** — `is not valid JSON: Unexpected identifier` |

프롬프트는 stdin 으로 빠지지만 **스키마 약 1.5KB 는 argv 로 나가야 한다.** 그 안에 `^` `|`
`\` 같은 cmd 메타문자가 들어 있다. Windows 에서 이게 통과하는지는 확인하지 못했다.
회수 스크립트가 찾은 실행 파일 경로와 shell 경유 여부를 보고에 남기게 해 뒀다.

## 2. 실측 — 비용을 가르는 것은 프로세스 수가 아니라 프롬프트 접두사다

**이 절은 오전에 쓴 내용을 정정한다.** 처음에는 "프로세스를 새로 띄울 때마다 cache
생성으로 과금된다"고 적었다. 배치를 실제로 돌려 보니 절반만 맞았다.

### 2.1 콜드 실행 세 번

| # | 조건 | cache 생성 | cache 읽기 | 출력 | 비용 |
|---|---|---|---|---|---|
| A | 프롬프트 2토큰, 규약 파일 없음 | 28,194 | 0 | 60 | **$0.11338** |
| B | 규약 파일 + ChangeSet 스키마, 원본 1건 | 28,888 | 0 | 1,506 | **$0.13062** |
| C | B와 **같은 규약 파일·같은 스키마**, 새 프로세스 | 5,853 | 22,873 | 733 | **$0.03530** |

A와 B는 10분 간격이었는데도 둘 다 cache 읽기가 0이다. B와 C는 새 프로세스인데 C가
22,873 토큰을 읽었다. 프로세스를 새로 띄웠는지는 상관이 없다. **프롬프트 접두사가 바이트
단위로 같은지**가 가른다.
접두사는 CLI 시스템 프롬프트와 도구 정의에 더해 cwd 의 규약 파일과 우리가 물린 스키마까지를 묶은 덩어리이고 응답의 `ephemeral_1h_input_tokens` 필드로 보아 이 캐시는 1시간짜리다 (TTL 경계는 직접 재지 않았다).

**설계 규칙이 하나 나온다. 인제스트 프롬프트의 접두사를 고정한다.** 문서마다 달라지는
내용을 앞에 두면 배치 전체의 캐시가 깨진다. 규약 파일과 스키마는 배치 내내 같은 바이트여야
한다.

### 2.2 5건 배치 실측

같은 규약 파일과 스키마로 원본 5건을 한 세션에 이어 붙였다 (`--resume`). 전건이
`changeset.ts` 의 관문을 통과했다.

| # | 비용 | cache 생성 | cache 읽기 | 출력 |
|---|---|---|---|---|
| 1 | $0.0353 | 5,853 | 22,873 | 733 |
| 2 | $0.0171 | 1,164 | 28,726 | 670 |
| 3 | $0.0160 | 896 | 29,890 | 640 |
| 4 | $0.0160 | 868 | 30,786 | 638 |
| 5 | $0.0167 | 876 | 31,654 | 690 |

**합계 $0.1011, 문서당 $0.0202, 61초.**

문맥이 쌓이면 문서당 비용이 오를 것이라 예상했는데 그렇지 않았다. cache 읽기가 문서당
약 900토큰씩 늘지만 읽기 단가가 낮아 비용은 평평하다. 표본 5건이라 더 긴 배치에서도
평평한지는 모른다. 긴 배치의 실제 한계로는 비용보다 컨텍스트 창과 품질이 먼저 올 것이다.

### 2.3 무엇이 프로세스를 건너 캐시되는가

2026-09-05 회수 스크립트 실행(`spikes/cli/record.mjs`)에서 §2.1 의 그림이 더 선명해졌다.
같은 규약 파일과 같은 스키마로 원본 3건을 **각각 새 프로세스**로 돌렸다.

| 사례 | cache 생성 | cache 읽기 | 비용 |
|---|---|---|---|
| kickoff | 6,303 | 22,873 | $0.0698 |
| contract | 6,243 | 22,873 | $0.0365 |
| cost | 6,245 | 22,873 | $0.0378 |

**읽기 22,873 이 세 번 다 똑같다.** 이건 CLI 자기 시스템 프롬프트이고 프로세스가 달라도
캐시로 붙는다. 반면 우리 규약 파일과 스키마에 해당하는 약 6,250 은 **매 콜드 프로세스마다
생성으로 다시 과금된다.**

§2.2 배치에서 2번째부터 생성이 900 대로 떨어진 이유가 여기 있다. `--resume` 이 캐시해 주는
것은 **우리 내용**이고 CLI 자기 접두사는 재개 없이도 붙는다. 두 절약이 겹쳐야 문서당
$0.02 가 나온다.

### 2.3 월 $50 환산

| 조건 | 문서당 | 월 처리량 |
|---|---|---|
| 콜드 캐시 · 문서당 프로세스 | $0.130 | 약 385건 |
| 접두사 고정 · 5건 배치 (실측) | $0.0202 | 약 2,475건 |

**6.4배 차이다.** 오전에 적은 "배치가 요건"이라는 결론은 그대로 서고 이유가 하나 늘었다.
배치는 세션 재개로도 아끼고 **접두사 캐시를 살려 두는 것으로도** 아낀다.

## 3. 바뀌는 것

### 3.1 사내 PC의 역할을 녹화로 줄인다

| 경로 | 어디서 만드나 | 사내 PC 몫 |
|---|---|---|
| A등급 (Claude Code) | **이 컨테이너에서 끝까지** | W2 — Windows spawn·경로·인용부호 확인 |
| B등급 (Gemini) | 인터페이스와 파서까지 여기서 | W3 — 실호출 **응답 녹화** |
| Codex | 인터페이스와 파서까지 여기서 | W3b — 실호출 **응답 녹화** |

사내 PC에서 개발 루프를 돌지 않는다. `spikes/cli/record.mjs` 를 한 번 실행해 3종 CLI의
원시 응답을 `spikes/fixtures/cli/*.json` 으로 떨구고 저장소에 커밋하면, 나머지 파서 작업과
회귀 테스트는 여기서 끝난다. **왕복 1회로 줄인다.**

### 3.2 배치 세션 재개는 M2 기본 경로다

M2 완료 기준에 비용 조건을 넣는다. "원본 1건이 끝까지 돎"만으로는 예산을 지킬 수 없다.
새 기준: **5건 이상 배치가 세션 재개로 돌고 문서당 비용이 $0.03 미만.**
2026-09-05 실측에서 5건 배치가 문서당 $0.0202 였다 (§2.2).

### 3.3 Lint LLM 4종은 배치 전용이다

§7.2.1 은 Lint LLM 4종을 Gemini로 보낸다. 사내에서 Gemini를 쓰지 못하면 이 부하가 전부
$50 예산으로 온다.

**이 절의 숫자를 두 번 고쳤다.** 근거가 된 실측이 두 번 바뀌었기 때문이다 (§10 에 경과).
지금 값은 위키 200쪽 기준 **배치 약 $11 · 페이지당 프로세스 약 $27** 이다.

$11 은 월 예산의 22% 다. 한 번 돌릴 때마다 그만큼이면 상시 실행할 물건이 아니다.
결과를 사람이 전부 검토해야 한다는 이유도 그대로다. 규칙은 이렇게 둔다.

- 배치 세션으로만 실행한다. 페이지당 프로세스 금지
- 사용자가 실행 시점을 고른다. 저장할 때마다 자동으로 돌리지 않는다
- 실행 직전에 **예상 비용과 남은 예산을 보여주고 확인받는다** (`core/tokens.ts`)

### 3.4 지출 계량기를 남은 문서 수로 보여준다

§9.4 의 "사용자가 상한을 직접 입력한다"는 유지하되 기본값을 월 $50 으로 둔다.
`total_cost_usd` 와 `modelUsage` 가 응답에 정확히 오므로(위 §2 실측) 추정이 아니다.
화면에는 `남은 배치 약 N회 · 문서 약 M건` 으로 환산해 띄운다. 사용자는 문서 단위로 생각한다.

## 5. 확실하지 않은 것

- Codex 인증 상태를 확인하지 않았다. 사내 PC 녹화에서 같이 본다
- Gemini B등급 응답의 실제 형태를 아직 못 봤다. 파서는 합성 입력으로 먼저 만들고 녹화가
  오면 회귀 테스트로 고정한다
- 월 $50 환산은 한 줄짜리 합성 원본으로 잰 것이다. 실제 사내 문서는 원본 텍스트가 훨씬
  길어 변동분이 늘어난다. 실제 문서로 재측정할 항목이다
- 배치 5건까지만 재봤다. 20건·50건에서도 문서당 비용이 평평한지는 모른다
- 접두사 캐시의 TTL 경계를 재지 않았다. 사용자가 한참 쉬었다 돌아오면 콜드 가격을 다시 낸다

## 6. 구현에서 나온 것

### 6.1 렌더러가 core 를 그대로 부르면 번들이 깨진다

검토 화면은 체크박스를 누를 때마다 승인 가능 여부를 다시 판정해야 해서 판정 함수를
렌더러에서 부른다. 그런데 `core/review.ts` 는 디스크를 읽으려고 `node:fs` 를 쓰고 그 안에서
`page.ts` 가 `node:crypto` 를 끌어온다. vite 빌드가 `"createHash" is not exported by
"__vite-browser-external"` 로 죽었다.

순수 판정만 `core/approve.ts` 로 갈랐다. 이 파일은 값 임포트로 Node 모듈을 쓰지 않는다.
번들 모듈 수가 109개에서 32개로 줄었다. 같은 실수가 다시 나지 않게 소스에 `node:` 값
임포트가 있는지 테스트로 잠갔다.

### 6.2 관문 8 실측

합성 킥오프 pptx 한 건을 인제스트해서 끝까지 돌렸다.

- 변경안 3건(`wiki/overview.md` · `wiki/entities/에이콤.md` · `wiki/sources/kickoff.md`)
- 관문 위반 0, 충돌 0, 깨진 인용 0
- **검토를 두 번 해도 `wiki/entities/` 가 비어 있었다.** 승인해야 파일이 생겼다
- 적용 뒤 `index.md` 가 다시 조립되고 스냅샷이 남았다

### 6.3 아직 없는 것

- **Electron 진입점(`main.ts`)이 없다.** IPC 계약과 `Store` 메서드까지 만들었고 `ipcMain`
  핸들러 등록은 창을 띄우는 코드와 함께 M7 에서 붙는다. 지금은 core 를 직접 불러 검증한다
- **"편집 후 승인"** — `DESIGN-SYSTEM.md` 가 카드 하단에 두라고 한 세 번째 버튼이다.
  편집기가 필요해 별도로 잡는다. 지금은 승인과 보류만 있다
- `.tsx` 는 타입체크와 vite 빌드로만 검증한다. Node 의 타입 제거는 JSX 를 다루지 못해
  테스트 러너에서 못 돈다. 그래서 판정 로직을 전부 core 로 내렸다

## 7. Electron 진입점에서 나온 것 (ROADMAP 2번)

### 7.1 Electron 33 은 이 앱을 띄우지 못한다

창을 띄우니 아무 로그 없이 멎었다. 원인은 **Electron 33 이 싣고 있는 Node 가 20.18.3
이고 거기에 `node:sqlite` 가 없다**는 것이다. `store.ts` 가 모듈 최상단에서 그걸 가져오므로
창이 만들어지기 전에 죽는다. 실패가 조용해서 로그로는 안 보였다.

M0 이 FTS5 를 `node:sqlite` 로 확정한 것은 이 컨테이너의 Node 22.22 에서 잰 결과다.
**Electron 안의 Node 는 다른 물건이라는 사실을 그때 확인하지 않았다.**

Electron 38 로 올려서 다시 쟀다.

| 확인 | 결과 |
|---|---|
| `node:sqlite` 존재 | 있음 (실험 기능 경고만 뜬다) |
| FTS5 가상 테이블 | 동작 |
| 한국어 prefix 질의 `갱신일*` | 적중 |

새 의존성을 넣지 않고 Electron 판본만 올려서 풀었다. `better-sqlite3` 같은 네이티브
모듈은 Electron 판본마다 다시 빌드해야 해서 오프라인 사내 설치에 부담이 된다.

### 7.2 preload 는 CommonJS 여야 한다

`sandbox: true` 를 켜면 ESM preload 를 못 쓴다. 샌드박스를 끄는 대신 preload 만 esbuild 로
번들해서 `preload.cjs` 로 내보낸다. 채널 이름이 `ipc.ts` 에서 그대로 인라인되므로 값이
갈라질 일이 없다.

### 7.3 실제로 뜬 것을 확인한 범위

`spikes/app/smoke.mjs` 가 앱을 띄워 8가지를 본다 — 창 제목, 첫 화면 렌더, `window.sb`
표면이 `SbApi` 와 같은지, `window.require` 가 없는지, IPC 왕복 2건, 창 넘침, 기본 버튼 색.

**diff 검토 UI 를 창 안에서 클릭해 보지는 못했다.** 그건 Vault 와 변경안이 있어야 하고
파일 대화상자를 거쳐야 해서 자동화 범위 밖이다. 검토 화면의 판정 로직은 core 테스트가,
끝까지 도는 흐름은 §6.2 의 실측이 덮는다.

이 스모크 검사는 **개발 컨테이너 전용**이다. 전역 playwright 와 Xvfb 가 필요하고
컨테이너가 root 라 `--no-sandbox` 를 붙인다. 사내 PC 는 돌리지 않는다.

## 8. B등급 경로 완성 (ROADMAP 3번)

`core/agent/gemini.ts`. CLI 가 스키마를 강제하지 못하므로 스키마를 프롬프트에 붙이고

- 펜스가 있는 경우와 없는 경우를 둘 다 받는다. 실측은 3건 다 펜스가 없었지만 n=3 은 작다

## 9. 캐시·계량기·라우팅 (ROADMAP 4·5·6번)

세 개가 서로 물려 있다. 캐시는 호출 수를 줄이고 계량기는 남은 예산을 알려 주며 라우팅은
상한에 닿았을 때 어디로 보낼지 정한다.

### 9.1 시맨틱 캐시 — 키는 파일 내용이다

`core/cache.ts`. 파일 내용의 SHA256 을 항목의 정체로 삼는다. 실측으로 확인한 분류다.

| 상황 | 결과 |
|---|---|
| 인제스트 직후 | `fresh=1` — 변경안을 아직 안 만들었으므로 보낸다 |
| 변경안을 만든 뒤 | `unchanged=1` — CLI 를 다시 안 부른다 |
| **이름만 바꿔 재인제스트** | `renamed=1 fresh=0` — 경로만 고치고 다시 묻지 않는다 |
| 내용을 바꿔 재인제스트 | `fresh=1` — 다시 묻는다 |

`proposedAt` 이 `null` 이면 내용을 알고 있어도 `fresh` 다. 인제스트만 하고 변경안을
아직 안 만든 상태에서 건너뛰면 그 문서는 영영 위키에 안 들어간다.

`manifest.json` 은 성공했을 때만 쓰고 임시 파일을 거쳐 바꿔치기한다.

### 9.2 지출 계량기 — 달러가 아니라 문서 수

`core/spend.ts`. 아는 것과 모르는 것을 나눈다.

- **안다** — `total_cost_usd` 누적. 실패한 호출도 센다. 성공만 세면 실제보다 낮게 나온다
- **모른다** — 남은 쿼터. 상한을 사용자가 안 넣으면 `unknown` 이고 경고도 폴백도 하지 않는다

화면에는 `claude-code · 남은 문서 약 1018건 · $0.00 / $50` 으로 띄운다.
지출은 **계정 단위**로 쌓는다 — Vault 마다 세면 상한을 두 배로 쓴다.

Gemini 는 비용을 보고하지 않아 호출 횟수만 센다 (§8.2).

### 9.3 라우팅 — 폴백은 상한에 닿았을 때만

`core/agent/router.ts`. [`PROVIDER-ROUTING.md`](PROVIDER-ROUTING.md) §3 표를 그대로 옮겼다.
실측 확인:

| 작업 | 평시 | claude 상한 도달 |
|---|---|---|
| `ingest.single` | claude-code | **gemini 로 전환** |
| `ingest.batch` | gemini | gemini |
| `schema.propose` | claude-code | **막힘** |

**미설치는 폴백 사유가 아니다.** 조용히 다른 공급자로 넘기면 왜 품질이 달라졌는지
사람이 모른다. 설정 문제로 보고 알린다.

### 9.4 같은 실수를 두 번 했다

렌더러가 `spend.ts` 의 `summarize` 를 부르자 `node:fs` 가 번들로 딸려 왔다.
§7 에서 `review.ts` 의 `node:crypto` 로 똑같이 당했다.

두 번째라서 목록을 손으로 적는 방식을 버렸다. 회귀 테스트가 **렌더러에서 시작해 상대
임포트를 따라가며** Node 모듈 사용을 찾는다. 일부러 어겨 보고 테스트가 실패하는 것까지
확인했다. 스모크 검사의 `window.sb` 표면 목록도 같은 이유로 `ipc.ts` 에서 뽑게 고쳤다 —
채널을 둘 늘리자 손으로 적은 목록이 바로 낡았다.

## 10. 한국어 글자수 환산과 작문 규칙 A/B (ROADMAP 8·9번)

### 10.1 한국어 1글자 ≈ 0.88토큰

프롬프트 접두사를 고정하고 뒤에 붙는 한국어 분량만 바꿔 다섯 번 호출했다
(`spikes/korean/tokens.ts`). 말뭉치는 이 저장소 문서의 한국어 산문이다.

| 글자 | 증분 토큰 | 토큰/글자 |
|---|---|---|
| 500 | 444 | 0.888 |
| 1,500 | 1,337 | 0.891 |
| 4,000 | 3,618 | 0.905 |
| 8,000 | 6,775 | 0.847 |

증분이 깨끗하게 선형이다. 같은 측정의 증분 비용에서 **cache 생성 1M 토큰당 $3.75** 도
나왔다 (큰 두 점이 3.62~3.81).

추정 상수는 **0.92** 를 쓴다. 처음에 0.9 로 잡았다가 4,000자 지점(0.905)에서 과소 추정이
나는 것을 테스트가 잡았다. 사람이 이 숫자를 보고 실행을 결정하므로 넉넉한 쪽으로 든다.

### 10.2 작문 규칙은 S1 을 없앤다 (n=20 × 2팔)

같은 합성 원본 20건을 두 번 돌렸다. A 는 `schema/AGENTS.md` 의 한국어 작문 절을 뺀 규약,
B 는 넣은 규약이다. 산출된 페이지의 `summary` 와 본문을 `detect.mjs` 로 채점했다.

| 팔 | 페이지 | S1/페이지 | S2/페이지 | 등급 | 걸린 규칙 |
|---|---|---|---|---|---|
| A 규칙 없음 | 20 | **2.00** | 1.00 | C 20건 | `C-11` × 40 |
| B 규칙 있음 | 20 | **0.00** | 1.00 | **A 20건** | 없음 |

**효과가 한 규칙에 몰려 있다.** 규칙을 안 주면 모델이 페이지마다 정확히 두 번
`~하고, ~하며,` 를 쓴다. 규칙을 주면 0 이 된다. 20건 전부 그랬다.

`E-1`(장문 결핍)은 양쪽 다 20/20 이다. 작문 규칙이 다루지 않는 항목이며 두세 문장짜리
개요에 100자 넘는 문장이 없는 것은 자연스럽다. **짧은 페이지에 `E-1` 을 적용하는 것이
맞는지는 따로 봐야 한다** — 지금은 규칙 쪽 문제로 보인다.

한계: 원본이 합성이다. 팔마다 한 세션으로 배치를 돌려 팔 안에서 문체가 수렴했을 수 있다.
모델 하나만 봤다.

### 10.3 이 측정이 §2.2 를 정정한다

A/B 두 팔의 비용이 각각 $0.83 으로 **문서당 $0.042**, 콜드를 뺀 재개분도 $0.042 였다.
§2.2 의 5건 배치는 문서당 $0.0202 였다.

배치 길이보다 **입력과 출력의 크기**가 갈랐다. 5건 배치는 원본이 한 줄짜리라 페이지도
짧았다. 실제 위키 페이지 분량으로 재니 M0 의 $0.049 에 가까워졌다.

**§2.2 에 "더 긴 배치에서도 평평한지는 모른다" 고 적어 둔 자리의 답이다.** 평평한지는
여전히 모른다. 대신 **합성 입력이 짧으면 비용을 절반 이하로 낮게 보이게 한다**는 것을 알았다.
`core/tokens.ts` 의 항목당 고정분을 세 실측 중 가장 큰 $0.049 로 되돌렸다.

## 11. 내장 MCP 서버와 질의 (ROADMAP 10·11번)

### 11.1 MCP 핸드셰이크 실측

SDK 를 넣지 않고 직접 붙였다. 필요한 것이 세 개뿐이라 40줄이면 된다.

```
<< initialize      protocolVersion 2025-11-25, clientInfo claude-code 2.1.261
>> (같은 판본을 그대로 돌려준다) capabilities.tools
<< notifications/initialized   ← 알림. 답하지 않는다
<< tools/list
<< tools/call      params.name · params.arguments
```

- **클라이언트가 말한 판본을 그대로 쓴다.** 우리가 고집할 이유가 없다
- 도구 이름은 `--allowedTools` 에서 `mcp__sb__search` 형태다. 서버 이름이 앞에 붙는다
- `--mcp-config` 는 본 명령에만 있다. `claude mcp list` 로는 연결 확인을 못 한다
- 도구가 던진 오류는 프로토콜 오류로 올리지 않고 **내용**으로 돌려준다. 모델이 읽고 고친다

### 11.2 읽기 경로가 끝까지 돌았다

위키 페이지 10장(그중 8장은 무관한 채움)을 놓고 **프롬프트에 없는 사실**을 물었다.

| 확인 | 결과 |
|---|---|
| 턴 수 | 6 — 도구를 실제로 불렀다 |
| 권한 거부 | 0건 |
| 두 페이지를 잇는 링크 추적 | 성공 (에이콤 → 베타테크) |
| 답변에 담긴 사실 | `2027-03-14` · `4억 2천만원` — 위키에만 있는 값이다 |
| 소요 · 비용 | 13.4초 · $0.1465 |

에이전트가 필요한 페이지만 당겨 갔다. 파일 복사 방식이면 10장을 다 밀어 넣어야 했다.

### 11.3 질의는 관문 8 을 건너뛰지 않는다

답변을 받으면 화면에만 띄운다. **보관을 눌러야 ChangeSet 이 되고 사람이 승인해야
`synthesis/` 페이지가 된다.** 인제스트와 같은 길을 간다.

근거로 페이지 경로 대신 **앵커 인용**을 받는다. 경로만 받으면 보관된 페이지의
주장에 출처가 없어 관문 4 에서 막힌다.

실측: 질의 → 보관 검토(위반 0 · 충돌 0 · 인용 칩 2개 정상) → 승인 → `synthesis/` 페이지
생성. 승인 전에는 `wiki/synthesis/` 가 비어 있었다. `log.md` 에 `query` 와 `ingest` 두 줄이
남았다.

### 11.4 `slugify` 만으로는 파일명이 안 된다

질문에 가운뎃점이 들어간 답변을 보관할 수 없었다. `slugify` 가 `·` 를 남기는데 관문 2 의
경로 정규식은 `[a-z0-9가-힣-]` 만 받는다. **답변을 만들고도 저장하지 못하는 상태**였다.

`security.ts` 에 `pageSlug` 를 뒀다. `slugify` 를 다시 걸어도 결과가 같아 관문 3 도 통과한다.

### 11.5 고치지 않고 적어 두는 것

`validateAnchors` 가 같은 깨진 앵커를 두 번 보고한다. 본문 인용과 `claims.source` 양쪽에서
잡히기 때문이다. 검토 화면에 같은 줄이 두 번 뜬다. M1 부터 있던 동작이라 이번 범위에서
건드리지 않았다.

### 11.6 패키징에서 주의할 것

CLI 가 MCP 서버를 **서브프로세스로 띄운다.** 패키징본에는 `node` 가 없으므로 Electron
자신을 `ELECTRON_RUN_AS_NODE=1` 로 돌린다. `mcp-entry.ts` 는 stdout 에 JSON-RPC 말고
아무것도 쓰지 않는다 — 한 줄이라도 섞이면 프로토콜이 깨진다.
