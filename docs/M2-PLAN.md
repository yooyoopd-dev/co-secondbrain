# M2 구현 방법 재검토 — 계정 분리와 월 $50 예산

작성 2026-09-05. [`PLAN.md`](PLAN.md) §7.1.1 · §9.4 · §12 · §13 을 고치게 만든 측정이다.

## 0. 새로 들어온 제약 두 가지

1. 개발에 쓰는 Claude Code 계정을 사내 PC에서 쓸 수 없다. 사내는 별도 기업계정이다.
2. **사내 기업계정의 토큰 예산이 월 $50이다.** 이건 개발 예산이 아니다. **앱이 실사용 중
   태우는 예산이다.** 그래서 제품 설계 제약이 된다.

기존 M2 계획은 "CLI가 사내 PC에만 있으므로 어댑터도 사내에서 만든다"를 전제했다.
측정해 보니 그 전제가 틀렸다.

## 1. 실측 — 개발 컨테이너에 CLI 3종이 다 있다

| CLI | 버전 | 스키마 강제 | 인증 |
|---|---|---|---|
| `claude` | 2.1.261 | `--json-schema` — 실행해서 확인 | **됨** |
| `gemini` | 0.58.0 | 없음 (B등급 확정, `PLAN.md` §7.1 과 일치) | 안 됨 — `GEMINI_API_KEY` 필요 |
| `codex` | 0.153.2 | `--output-schema` 플래그 존재 | 미확인 — `--skip-git-repo-check` 선행 필요 |

A등급 경로 실행 결과:

```
claude -p "2+3은? n에 숫자만." --json-schema '{...}' --output-format json \
       --disallowedTools Read Write Edit Bash Glob Grep WebFetch WebSearch Task
→ structured_output: {"n":5}      num_turns=2      is_error=false
```

`PLAN.md` §7.1 의 A등급 경로가 **사내 PC 없이 이 컨테이너에서 그대로 돈다.**

### 1.1 주의 — 서브프로세스가 부모 세션 id를 물고 나온다

위 실행의 응답 `session_id` 가 부모 세션의 id와 같았다. 환경변수
`CLAUDE_CODE_SESSION_ID` 가 상속되기 때문이다. Electron 앱에서는 이 변수가 없으므로
제품에서는 생기지 않는다. 다만 **개발 중 `--resume` 배치를 시험할 때 부모 세션과 충돌**하므로
어댑터는 자식 프로세스 환경에서 이 변수를 지우고 띄운다.

## 2. 실측 — 콜드 프로세스 1회의 비용 바닥

같은 실행의 과금 내역이다.

| 항목 | 토큰 |
|---|---|
| cache 생성 | 28,194 |
| input (우리 프롬프트) | **2** |
| output | 60 |
| **`total_cost_usd`** | **$0.11338** |

**우리 내용은 2토큰이고 나머지 전부가 CLI 자기 시스템 프롬프트이며 프로세스를 새로 띄울 때마다 이 덩어리가 cache 생성으로 다시 과금되므로 프롬프트를 줄이는 최적화는 이 구조 앞에서 거의 효과가 없다.** M0 §7.1.1 이 같은 구조를 다른 입력으로 측정했고
(`$0.130`, 4줄 회의록) 이번 수치가 그 **바닥**을 확인해 준다 — 프롬프트를 아무리 줄여도
콜드 실행 1회는 약 $0.11 아래로 내려가지 않는다.

표본 n=1 이다. 다만 이 값은 입력 크기와 무관한 고정 오버헤드라서 바닥값으로 쓸 만하다.

### 2.1 월 $50 환산

| 방식 | 문서당 | 월 처리량 |
|---|---|---|
| 문서당 프로세스 (M0 실측 $0.130) | $0.130 | 약 **385건** |
| 배치 + 세션 재개 (M0 실측 $0.049) | $0.049 | 약 **1,020건** |

**2.6배 차이다.** §7.1.1 이 "배치가 필수"라고 쓴 근거가 예산 숫자와 만나면서 선택지에서
요건으로 바뀐다.

## 3. 바뀌는 것

### 3.1 사내 PC의 역할을 녹화로 줄인다

| 경로 | 어디서 만드나 | 사내 PC 몫 |
|---|---|---|
| A등급 (Claude Code) | **이 컨테이너에서 끝까지** | W2 — Windows spawn·경로·인용부호 확인 |
| B등급 (Gemini) | 인터페이스와 파서까지 여기서 | W3 — 실호출 **응답 녹화** |
| Codex | 인터페이스와 파서까지 여기서 | W3b — 실호출 **응답 녹화** |

사내 PC에서 개발 루프를 돌지 않는다. `spikes/cli/record.mjs` 를 한 번 실행해 3종 CLI의
원시 응답을 `spikes/fixtures/cli/*.json` 으로 떨구고 저장소에 커밋하면, 나머지 파서 작업과
회귀 테스트는 여기서 끝난다. **왕복 1회로 줄인다.**

### 3.2 배치 세션 재개는 M2 기본 경로다

M2 완료 기준에 비용 조건을 넣는다. "원본 1건이 끝까지 돎"만으로는 예산을 지킬 수 없다.
새 기준: **10건 배치가 세션 재개로 돌고 문서당 비용이 $0.06 미만.**

### 3.3 Lint LLM 4종은 기본 비활성 + 배치 전용

§7.2.1 은 Lint LLM 4종을 Gemini로 보낸다. 사내에서 Gemini를 쓰지 못하면 이 부하가 전부
$50 예산으로 온다. 위키 200쪽 전수 스캔을 페이지당 프로세스로 돌리면 **약 $22.6** —
한 번에 월 예산 절반이다.

- 기본 비활성. 사용자가 명시적으로 실행한다
- 배치 세션으로만 실행한다. 페이지당 프로세스 금지
- 실행 직전에 **예상 비용과 남은 예산을 보여주고 확인받는다**

### 3.4 지출 계량기를 남은 문서 수로 보여준다

§9.4 의 "사용자가 상한을 직접 입력한다"는 유지하되 기본값을 월 $50 으로 둔다.
`total_cost_usd` 와 `modelUsage` 가 응답에 정확히 오므로(위 §2 실측) 추정이 아니다.
화면에는 `남은 배치 약 N회 · 문서 약 M건` 으로 환산해 띄운다. 사용자는 문서 단위로 생각한다.

## 4. 수정한 M2 작업 순서

### 이 세션에서

| # | 작업 | 검증 |
|---|---|---|
| 1 | `AgentCli` 인터페이스 + `claude-code` 어댑터 (격리 디렉터리 · `--json-schema` · `structured_output` 회수 · 부모 세션 변수 제거) | 실호출 1회로 관문 7개를 통과하는 ChangeSet |
| 2 | 배치 러너 — `--resume` 세션 재개, 실패 문서만 재시도 | 10건 배치 문서당 $0.06 미만 |
| 3 | 비용 계량기 — `total_cost_usd` 누적, 상한 도달 시 정지 | 픽스처로 상한 동작 테스트 |
| 4 | 녹화·재생 하네스 | `npm test` 가 네트워크 없이 통과 |
| 5 | B등급 파서 — 펜스드 블록 회수 + JSON Schema 검증 + 1회 재요청 | 녹화·합성 응답 문자열로 테스트 |
| 6 | diff 검토 UI — 기존 `applyChangeSet` 관문에 연결 | 승인 전에는 디스크가 안 바뀐다 |

실호출 예산: 개발 전체에서 10~20회, 약 $2. 테스트는 픽스처로 돌므로 반복 비용이 0이다.

### 사내 PC에서 (녹화 1회)

`spikes/cli/record.mjs` 한 번으로 W2 · W3 · W3b 를 동시에 처리한다.

## 5. 확실하지 않은 것

- Codex 인증 상태를 확인하지 않았다. 사내 PC 녹화에서 같이 본다
- Gemini B등급 응답의 실제 형태를 아직 못 봤다. 파서는 합성 입력으로 먼저 만들고 녹화가
  오면 회귀 테스트로 고정한다
- 월 $50 환산은 M0 의 문서당 비용($0.130 · $0.049)을 그대로 쓴 것이다. 문서 크기가 4줄
  회의록보다 크면 변동분이 늘어난다. 실제 사내 문서로 재측정할 항목이다
