# 오프라인 설치 · 운영 가이드

인터넷이 없는 Windows PC 에서 co-secondbrain 을 쓰는 방법입니다. ROADMAP 21번.

**exe 파일 하나면 됩니다.** 설치하지 않습니다. 인터넷에 붙지 않습니다. 아무것도 자동으로
받지 않습니다.

---

## 1. 받아서 두기

[릴리스](https://github.com/yooyoopd-dev/co-secondbrain/releases/latest)에서
`co-secondbrain-<판>-portable.exe` 를 받습니다. 인터넷이 되는 곳에서 받아 USB 나 사내
파일 공유로 옮기십시오.

두 번 누르면 뜹니다. 설치 권한이 없어도 됩니다. 파일 하나를 아무 폴더에나 두고 쓰다가
지우고 싶으면 그 파일만 지우면 끝입니다.

| | |
|---|---|
| 대상 | Windows x64 |
| 크기 | 약 97 MB |
| 설치 | 안 합니다 |
| 자동 업데이트 | 없습니다 |
| 텔레메트리 · 크래시 리포터 | 없습니다 |

처음 켤 때 SmartScreen 이 막을 수 있습니다. 코드 서명 인증서를 안 붙였기 때문입니다.
`추가 정보` → `실행` 으로 넘어갑니다.

## 2. Vault 만들기

첫 화면에 두 가지가 있습니다.

- **새 Vault 만들기** — 빈 폴더를 고릅니다
- **기존 Vault 열기** — 이미 만든 폴더를 고릅니다

Vault 는 그냥 폴더라서 Git 도 데이터베이스도 필요 없고 Obsidian 으로 같이 열어도
됩니다. 앱을 지워도 지식은 파일로 남습니다.

만들면 이런 모양이 됩니다.

```
00_INBOX/       받은 편지함. 여기 파일을 떨어뜨려 두면 앱이 알려 준다
01_SOURCES/     넣은 원본 파일
02_NOTES/       위키. sources · entities · concepts · synthesis · assets
03_OUTPUT/      슬라이드 등 내보낸 것
09_TEMPLATES/   규약과 나의 핵심 맥락
.sb/            앱이 만들고 앱만 읽는다. 손대지 않는다
```

번호를 붙여 둔 것은 작업 순서를 그대로 보이려는 것입니다. 파일 목록을 열면 순서대로 놓입니다. `.sb/` 는 점으로
시작해서 Obsidian 이 아예 무시합니다 — 노트 사이에 안 섞입니다.

## 3. LLM CLI 붙이기

좌측 아래 **[설정]** → `LLM CLI 설정`.

**설치 여부는 앱을 켤 때 한 번만 봅니다.** 방금 깔았다면 앱을 다시 켜야 목록에 뜹니다.

| 고르는 것 | 뜻 |
|---|---|
| 자동 | 작업 종류마다 알맞은 쪽으로 보냅니다. 권장 |
| 하나로 고정 | 그 CLI 가 못 맞추는 작업은 **거절합니다.** 다른 데로 안 넘깁니다 |

왜 결과가 달라졌는지 모르는 것보다 안 도는 편이 낫다고 봤습니다.

CLI 자체는 사내에서 따로 깔아 둔 것을 씁니다. 앱이 받아 오지 않습니다.

## 4. 나의 핵심 맥락 세 문항

**[설정]** → `나의 핵심 맥락`. 세 가지를 적습니다.

1. 나는 누구인가
2. 왜 기록하는가
3. 어떤 산출물을 원하는가

LLM 이 매 호출에서 먼저 읽습니다. 같은 원본이라도 누가 왜 쌓는지 알면 고르는 것이
달라집니다. 정본은 `09_TEMPLATES/me.md` 파일 하나라 Obsidian 에서 바로 고쳐도 됩니다.

**이 파일은 동기화가 올리지 않습니다.** CO 영역에서도 동료에게 가지 않습니다.

안 적어도 됩니다. 비어 있으면 프롬프트가 한 바이트도 안 늘어납니다.

## 5. 문서 넣기

좌측 위 **[문서 추가]**. 넣기 전에 바로 위의 **열람 등급**을 고릅니다 — 기본은 `사내`
입니다. 넣고 나서 고치게 하면 아무도 안 고칩니다.

두 단계로 갑니다.

1. **로컬 추출** — 텍스트와 앵커를 로컬에서 뽑는 단계. LLM 이 관여하지 않고 돈도 안 든다
2. **위키 갱신** — CLI 를 불러 변경안(ChangeSet)을 받는 단계

**LLM 은 디스크에 직접 쓰지 않습니다.** 변경안이 diff 화면에 뜹니다. 사람이 승인해야 파일이
됩니다. 승인 전에는 앱 메모리에만 있어서 앱을 끄거나 Vault 를 닫으면 사라집니다. 그때
앱이 먼저 물어봅니다.

체크박스로 일부만 승인해도 됩니다. 거부한 것은 아예 안 쓰입니다. 내용을 고쳐서 승인하면
**관문을 다시 통과해야** 들어갑니다.

`00_INBOX/` 에 파일을 떨어뜨려 두면 좌측 위에 뜹니다. 비어 있으면 아무것도 안 그립니다.

## 6. 묻고 내보내기

검색창에 물으면 한국어 검색으로 후보 페이지를 고른 뒤 LLM 이 인용을 붙여 답합니다.
그 답을 보관하면 `02_NOTES/synthesis/` 페이지로 검토 화면을 거쳐 들어갑니다.

**[판단 검사]** 는 LLM 판단이 필요한 검사 4종입니다. 계산으로 되는 7종은 늘 돌고 있어
따로 부를 것이 없습니다. 결과는 전부 제안이고 자동으로 고치지 않습니다.

**[슬라이드]** 는 Marp 형식으로 `03_OUTPUT/` 에 내보냅니다.

## 7. 동료와 같이 쓸 때 (CO 영역)

개인 Vault 는 동기화가 없습니다. 내용이 이 컴퓨터를 떠나지 않습니다.

CO 영역은 사내 CO-Hub 서버를 거칩니다. **사내망만 씁니다. 인터넷은 안 씁니다.**
서버 설치는 [`HUB.md`](HUB.md) §2 를 보십시오.

**[설정]** → `허브 연결` 에서 사내 URL 과 토큰을 넣습니다.

**토큰은 Vault 폴더에 안 씁니다.** Windows 자격 증명 저장소(DPAPI)에 암호문으로 들어갑니다.
Vault 폴더는 통째로 복사되고 백업되므로 거기 적으면 복사본마다 토큰이 딸려 갑니다.

충돌이 나면 좌측에 뜹니다. 세 칸 화면에서 사람이 고릅니다. 자동 병합은 안 합니다.

## 8. 되돌리기와 백업

변경안을 적용할 때마다 `.sb/history/` 에 스냅샷이 쌓입니다. 되돌리기의 단위는 적용 1회
입니다 — 그 변경안이 건드린 페이지를 한꺼번에 되돌립니다.

**아직 되돌리기 화면이 없습니다.** 되돌리는 코드(`core/history.ts` 의 `restore`)는 있는데
버튼이 안 붙었습니다. 지금은 `.sb/history/` 에서 손으로 꺼내야 합니다.

**개인 Vault 는 동기화도 백업도 대상이 아닙니다.** 폴더를 통째로 복사해 두십시오.
CO 영역은 허브 DB 가 판을 관리합니다.

## 9. 막혔을 때

무엇이든 실패하면 좌측 아래에 오류 개수가 뜹니다. 눌러서 **복사**하면 사유가 통째로
클립보드에 들어갑니다. 그대로 붙여 보내 주십시오.

**복사본에는 파일 이름과 토큰이 들어 있지 않습니다.** 앱이 지우고 담습니다. Vault 경로도
안 들어갑니다 — 그건 설정 화면에서만 보여 줍니다.

자주 나는 것들입니다.

| 증상 | 볼 곳 |
|---|---|
| CLI 가 목록에 없다 | 앱을 다시 켭니다. 탐지는 켤 때 한 번입니다 |
| 허브 연결이 거절된다 | 사내망인지, URL 과 토큰이 맞는지 |
| 변경안이 사라졌다 | 승인 전에는 메모리에만 있습니다. 앱을 껐다면 다시 제안해야 합니다 |
| 추출이 실패한다 | DRM 이 걸린 파일은 먼저 풀어야 합니다 |
| PDF 에서 아무것도 안 나온다 | 스캔본입니다. 앱이 경고를 답니다. OCR 이 필요합니다 |

## 10. 판을 올릴 때

새 exe 를 받아 옛 파일을 덮어씁니다. **Vault 는 손대지 않습니다** — 폴더와 마크다운이라
판이 올라가도 그대로 열립니다. 릴리스에서는 이전 판 exe 를 지워, 받는 사람이 목록에서 옛
파일을 집어 가는 일을 막습니다.

## 11. 안 하는 것

- 클라우드에 안 붙습니다. 밖으로 나가는 통로는 사내에서 예외로 허용된 CLI 3종뿐입니다
- 자동 업데이트 · 텔레메트리 · 크래시 리포터가 없습니다
- 자동 병합 · 자동 재작성을 안 합니다. 디스크에 닿기 전 마지막 관문은 늘 사람의 승인입니다
