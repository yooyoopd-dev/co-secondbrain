# 참고: Karpathy "LLM Wiki" 패턴 요약

출처: <https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f#file-llm-wiki-md>
(2026-09-03 확인. 아래는 원문 요약이며 원문 자체가 아닙니다.)

## 핵심 주장

전통적 RAG는 질의할 때마다 원본에서 검색·합성을 반복한다.
LLM Wiki는 대신 LLM이 **지속적으로 축적되는 위키**를 점진적으로 짓고 유지하게 한다.
"위키는 지속적이고 누적되는 산출물이다. 상호 참조는 이미 거기 있고, 모순은 이미 표시돼 있다."

## 3계층

| 계층 | 소유자 | 내용 |
|---|---|---|
| Raw Sources | 불변 | 원본 문서. LLM은 읽되 수정하지 않음 |
| The Wiki | LLM | 요약·엔티티·개념·합성 페이지 (Markdown) |
| The Schema | 사람 | `CLAUDE.md` / `AGENTS.md` — 구조·관례·워크플로 정의 |

Schema 계층이 LLM을 "범용 챗봇"이 아니라 **규율 있는 관리자**로 만든다.

## 3가지 동작

- **Ingest** — 원본 추가 → LLM이 읽고 → 사용자와 요점 논의 → 요약 작성 → 인덱스 갱신 →
  관련 엔티티·개념 페이지 개정. 원본 1건이 페이지 10~15개를 건드릴 수 있음.
- **Query** — 위키에 질문. LLM이 관련 페이지를 찾아 합성. 그 답을 다시 위키에 편입 가능
  → 탐색이 지식으로 누적됨.
- **Lint** — 주기적 건강 점검: 모순, 낡은 주장, 고아 페이지, 누락된 상호 참조, 데이터 공백.

## 보조 파일

- `index.md` — 카테고리별 콘텐츠 카탈로그. 임베딩 RAG 없이 LLM이 페이지를 찾게 해줌.
- `log.md` — 인제스트·질의·린트의 시간순 추가 전용 기록.

## 왜 작동하는가

위키가 방치되는 원인(상호 참조 갱신, 일관성 유지, 모순 기록)은 전부 지루한 유지보수인데,
LLM이 거의 공짜로 처리한다. 사람은 큐레이션·방향·분석에 집중한다.
Vannevar Bush(1945)의 Memex 개념과 통한다 — 문서 사이의 **연결**이 문서만큼 가치 있다.

## co-secondbrain이 원안과 다르게 가는 지점

| 원안 | 본 프로젝트 | 이유 |
|---|---|---|
| LLM이 `index.md` 유지 | 앱이 front-matter에서 **자동 생성** | 팀 동시 편집 시 최대 충돌원. 결정론적이면 충돌 자체가 없음 |
| `log.md` 단일 파일 | `journal/<날짜>--<사용자>.jsonl` 분할 | 공유 폴더에서 단일 파일 동시 append는 손상 위험 |
| LLM이 파일을 직접 씀 | LLM은 **변경안**만 내고 사용자 승인 후 앱이 씀 | 직장 사용에 필요한 감사 추적·되돌리기 |
| 인용 형식 자유 | **앵커 인용 강제** (`[^src#slide-12]`) | 원문 위치로 클릭 점프. 무출처 문장은 Lint가 잡음 |
